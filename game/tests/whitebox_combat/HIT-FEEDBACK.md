# 白盒命中反馈V1

2026-11-16。用户要求直接在白盒调整并体验；通用方案的背景见[设计分析](../../../docs/combat-hit-feedback.md)。本批只接白盒，未同步正式主线。

## 操作与表现

- F4：新命中反馈开/关对照。伤害、冷却、技能控制规则保持原样，反馈停顿时长本身是本轮调参项。
- F5：声音开/关，关闭会立即停止当前白盒声音，不改全局音量。
- R：清理特效、局部停顿、回弹和当前声音，并重置战斗；F4/F5选择保持。9：主靶补60血；8：群靶。
- 原键位见[操作表](CONTROLS.md)，地面普攻仍站定，取消与后跳白影保持。镜头未加震动。

命中事件统一进入`CombatWhiteboxHitFeedback`。沿用已有真实伤害后的impact信号，不在出招时伪造命中。当前信号只提供目标框中心，白盒通过该中心精确匹配目标，再选择朝向攻击来源的受击框侧边作近似接触点；未宣称真实武器像素接触，目标重合情况下的歧义仍是以后扩展事件载荷的边界。

普通击停3个60Hz帧，多段中间击1帧，重击/终结/击杀4帧。命中时先显示当前接触动作帧，双方攻击/受击动画与敌人AI/物理同步停止；群攻在同一物理帧取最大值，不把目标数加成总停顿。UI/音效/小粒子继续，未调用全场time_scale。

敌人短闪使用暖白Shader，保留轮廓；每次受击独立启动已有hurt逐帧，并有约3/6/10px起始幅度的显示回弹后迅速恢复。碰撞体不位移，不把下一击推空，不重复重置敌人AI硬直。霸体仅有减弱的局部反应/短闪，保持真实攻击姿势与原受控规则。

命中火花复用已入库`projectile.png`的Alpha，以Shader着色并由32个预建Sprite池驱动；声音复用已入库strike、hit三个变体及heavy，6个预建音频声部，同帧群攻命中音限一次。多段中间击更轻，末段强调。音效与动作图集启动前加载，不在命中时读取GPU或生成图片；退出清理音频流引用。无界面测试只验证声音资源与路由，不启动实时混音播放，避免高速固定帧退出时异步播放引用残留；实际声音播放仅在桌面模式验收。

## 验证

67项独立专项通过、0失败，`game/build/hit-feedback-tests.log`。新增6项覆盖：

1. 实际普攻命中后双方时钟停止、接触点在受击侧、真实纹理粒子与Shader短闪出现。
2. 空挥无伤害反馈；一刀三目标逐个反馈，但攻击者停顿不叠加，固定粒子池不增长。
3. 五连伤害仍为5次，四次轻脉冲加一次重终结，碰撞体不被显示回弹移动。
4. 霸体有短闪但不被打断/挑空；弹体也走共用反馈。
5. 重置清理粒子/停顿/显示回弹，F4关闭保留真实伤害与旧基线。

原挑空测试改为先验证命中时已施加负向冲量，再等待共同停顿结束后观察升空；落地断言等待真实倒地。不同于旧仅攻击者停顿的壁钟，未通过减少伤害或跳过受控来消除失败。原61项输入、站定、动画、取消与攻防继续通过。

GPU原帧复核：`game/build/qa/hit-feedback-basic/`与`hit-feedback-heavy/`，确认接触动作帧、暖白受击轮廓、局部火花和群攻显示。录制不作为性能样本。初次不限帧的后台profile因渲染远快于物理，40渲染帧便重置技能，未覆盖真实命中，已弃用；复跑必须用下列60帧上限，确认日志出现实际命中。

```powershell
node tools/godot.mjs run -- --windowed --resolution 1280x720 --max-fps 60 res://tests/whitebox_combat/main.tscn -- --profile-whitebox
```

最新帧耗时/原生试玩与完整工程检查结果记录在[工程进度](../../progress.md)。本批复用现有资源，没有新增正式动作素材；回弹是已有hurt动作的辅助呈现，不能登记为新逐帧动作完成。还需用户确认主观力度与音效，正式主线接入另行安排。
