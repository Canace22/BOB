# 地图与场景制作：V2 → 可玩场景

打开 [地图与场景工作台](./scene-lab.html)。它直接读取当前游戏的数据，默认展示新增的肋骨游廊；可切换鲸口、胃库、肋骨、肺缘四区。原画不作为工作台背景。

## 这轮“提取”实际做了什么

这里的提取是**空间分析、结构简化、关卡几何重建与分层重绘**，不是从概念图中直接抠出一套已完成的精灵或可拼接地块。

1. 从原画读出器官的形态语言、空间高度、交通方向、光向与关键互动意图。
2. 将意图重建成 `levels.js` 中可编辑的世界坐标、平台、设施、触发条件与连接出口。
3. 远景使用独立生成的纯环境图，避免把分镜人物和不可碰撞的平台烘焙进背景。
4. 中景器官结构由程序模块重绘；鲸口与肋骨区的骨台采用参考 L09 重建的透明骨质组件，按实际地图位置组装；其他地形与设施依据地图几何绘制。
5. 主角、生物、粒子与交互提示属于独立动态层。

目前没有做原画逐像素切割或重构原画中的全部构筑物。透明骨台是参照 L09 材质重建的独立组件；干净远景是独立生成的新素材。来源与完整提示词见 [assets/README.md](./assets/README.md)。骨台绘制裁去上缘装饰突起，将主横边贴合碰撞高度，以固定比例裁切和重复；透明孔洞保留，左右不超出可站立范围，资源加载失败时回退到程序地形。

## 数据与渲染职责

| 文件 | 职责 |
| --- | --- |
| `levels.js` | 四区地图真值：世界宽度、平台矩形、攀爬范围、升降参数、摆荡参数、上升流、交互点、记忆、出口、检查点 |
| `mechanics.js` | 升降台位置和骨环摆荡端点的共享计算函数；游戏与工作台使用相同公式和秒数单位 |
| `ecology.js` | 三处栖息地的前置机制、居民、恢复时长与三态查询；引擎、画面、地图和手记共享 |
| `field-guide.js` | 根据实际出口条件与旅程状态生成地图、修复状态和生态手记；隐藏未探索区域详情 |
| `engine.js` | 碰撞、能力、设施状态、开关条件、交互判定、失败恢复与实际通关规则 |
| `scenes.js` | 场景配置与器官视觉模块的组合数据，由游戏渲染层消费 |
| `renderer.js` | 水体远景、器官中景、地图实体、角色及反馈的分层绘制 |
| `assets/abyss-backdrop-v2.png` | 独立生成的纯环境远景；没有角色和玩法平台 |
| `assets/bone-ledge-v2.png` | 参考 L09 重建的透明骨台组件，用于鲸口与肋骨区；裁切参数在 `scenes.js` 中 |
| `scene-lab.html` / `scene-lab.js` | 同源地图检查工具，不复制一份碰撞或设施数据 |

## 工作台可以检查什么

- 四区使用实际 `width × 740` 的等比坐标；主角出生点标为 30 × 48，用于判断尺度。
- 地形层显示平台实体矩形、条件地面、开门前的门和排流前危险区；不会把多个状态误说成同一实时状态。
- 设施层显示攀爬矩形、升降台最低 / 最高行程、完整摆荡轨迹以及上升流范围。
- 时间滑块 / 播放按钮调用共享运动公式。升降设施按已供能预览，方便审查全程位置。
- 互动层显示交互物、记忆及连接出口。每个实体可点击查看原始参数。
- 路线层显示出生点、检查点和建议动线。动线是设计标注，不是自动寻路结果，也不证明该动作一定能完成。
- 原始 JSON 和 `levels.js` 链接用于人工编辑；保存数据并刷新即可让游戏与工作台同时采用新地图。工作台不写文件。

## 尚需精化的部分

- **镜头**：工作台是全区总览，游戏是横向视窗；应在真实镜头下持续审查设施预告、头顶净空和落点可见性。总览上的清晰不等于镜头内的清晰。
- **物体尺度**：统一世界坐标已建立，但画面中骨骼、平台厚度、攀网抓握点与主角身体的比例仍需美术迭代。
- **器官辨识**：程序中景能明确分区，尚未达到逐区手绘场景包的细节与独特性；干净远景属于通用空间气氛，不能独自承担胃 / 肺 / 肋骨的识别。
- **素材生产**：下一步若做精制场景，应逐区产出无角色环境层、独立透明骨架 / 组织组件、可拼接平台材质和设施状态图，并逐项对齐 `levels.js`；不应继续把整张分镜原画铺到可玩世界。
- **语义与规则**：视觉路标、机关触发条件和安全恢复规则需要结合实际试玩验证；图例展示几何，不替代通关与失败恢复测试。
