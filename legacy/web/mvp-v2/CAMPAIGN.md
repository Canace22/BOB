# V5.2 战役来源与首批实现

战役按 V5.2 的房间、能力和进程建立，使用独立存档 `whalefall-v52-save`。旧四区原型的 `whalefall-v2-2d-save` 不迁移成战役进度。当前批次开放 R1-01 至 R1-05；R1-06 / R1-07 保留设计数据与能力门，等待 A2 / A3 批次。世界地图中的其他区域是来源元数据，不代表已经可玩。实际验收与线上状态以 [progress.md](progress.md) 为准。

## 来源与坐标边界

- 用户指定的[简版设计](http://10.11.140.20:8765/simple/)与[完整设计](http://10.11.140.20:8765/full/)是本轮依据。完整页访问遇到502，禁用代理直连也超时，因此本批使用素材制作时保存的[完整页面](../assets/source/whalefall-v5-2-complete/inventory/full-source.html)、[纯文本](../assets/source/whalefall-v5-2-complete/inventory/full-source.txt)和[来源索引](../assets/source/whalefall-v5-2-complete/inventory/source-index.json)，不声称实时源站已核验。
- [场景需求清单](../assets/source/whalefall-v5-2-complete/inventory/full-scene-inventory.json)保存36房的稳定 ID、名称、尺寸、房卡和结构图链接。[campaign-levels.js](campaign-levels.js) 的 `WORLD_ROOMS` 来自该清单，`WORLD_EDGES` 来自完整页面的连接、门槛和捷径表；39条边按 `E01`–`E39` 去重，保留首次开闩侧与前置条件。
- 源站每房结构图为 `full/maps/rooms/<房间ID>.svg`，另有 `full/data/鲸体位置与连接.json` 和 `full/data/地图21项设计.json`。精确结构文件尚未取到，原画不能替代碰撞数据；本批所有房间明确标记 `layoutStatus: adapted-from-source`。
- 尺寸按 **1U = 48游戏像素 = 主角身高** 换算；主角碰撞盒为30×48像素。房间使用自己的宽高，镜头可纵向移动。实体位置以脚底或来源指定挂点为准，`spawn` 使用主角左上角。
- 源文给出的敌人、奖励、锚环位置保留 `sourceAtU` 或对应数据；未给精确坐标的丘面、坡度、平台厚度和宽度是试玩适配，不能称为原布局逐点复刻。R1-01 中文通关流程指向右侧，而旧英文绘图词称唯一出口在左；本批选择中文流程、保留唯一 E01，待源结构文件恢复后复核方向。

## 操作与数值

默认操作如下，可在战役设置中重绑。提示应读取绑定配置，不沿用旧四区 E共鸣 / F交互。

| 操作 | 默认按键 |
| --- | --- |
| 移动 / 跳跃 | A、D / Space |
| 短击 / 重鸣 | Q / R |
| 交互、营地登记、取奖励 | E |
| A1贴流冲 | Shift，获得后可用 |
| 调息 / 灯罩 | H / L |
| 地图 / 暂停 | M / Escape |

明确来自源设计：步速 **3.2U/s = 153.6px/s**；初始生命4格、每4枚固定碎片升1格、最多6格；蓄振上限4，重鸣和调息耗2，调息恢复1生命；A1距离2.6U、每次离地一次、落地刷新。首批短击回蓄振量、跳跃速度 / 重力、攻击伤害、敌人生命、攻击有效时间、冲刺耗时 / 冷却和调息时长是 [campaign-engine.js](campaign-engine.js) 中集中列出的试玩调参，不冒充源文精确值。

尸蟹预告0.65秒、横扫1.6U、恢复0.7秒。负壳蟹横扫预告0.8秒 / 恢复0.75秒，壳砸预告1.1秒 / 恢复1秒；半血后第二扫有独立0.55秒预告。待机身体不自动伤人，战后立即停伤并保存。静态素材配合程序移动和状态提示，尚不具备正式逐帧动作动画。

A2–A5、六模块与两槽配置、P/B/S完整进程、骨音旅行、其他区域敌人与Boss、后续生态和终局留待对应批次；不能因为元数据或素材已在仓库就显示为已实现。新增批次继续沿用源稳定 ID，尤其不能因“食道闩”改名而更改 `SC_ESOPHAGUS`。

## 接入验收

1. 核对36房 / 39边元数据和首批各出口条件；所有出生点、返程点必须落在当前碰撞面。
2. 用真实键盘走完外伤坡、须筛、舌台、Boss与三段短冲，验证未获能力时不能越门；高台、斜坡和凹沟必须实机对齐。
3. 分开验证短击、重鸣、受伤、调息中断、半血二扫与战后授能；教程失足不能消耗生命或变成下层绕路。
4. 验证营地、死亡、刷新与回访保留永久状态；Boss警戒和攻击等临时状态重置；新旧存档互不覆盖。
5. 按[桌面验收 Skill](../.agents/skills/bob-desktop-verification/SKILL.md)检查导出资源、错误回退、性能与 `/BOB/` 发布路径，记录执行结果；本页定义范围，不代替验收证据。
