# 拾潮者左右向动作：制作候选与检查记录

这里保存为 BOB 玩家补动作的源图、提示词和 Framecraft 工程。当前可查看[左向六姿势短跳候选](left-jump/README.md)和[原片面右11帧空中片段](video-jump-right/README.md)，左右分别保留装备挂点。**两者都还不是完整可接入的跳跃；左右跑动及其他对应动作仍未补齐。** 左向跑动的[四关键图](left-run/keyposes-v02.png)另保留作相位参考。

本批只保存在 `assets/source/`，随制作批次本地入库。没有写入正式运行素材、没有修改游戏加载或状态机，没有发布，也没有取得用户美术认可。左右样稿的局部进展不能作为“玩家左右动作齐全”的交付。

Git 保留最佳四姿势候选、提示词、时间线和检查报告。以下链接中的被拒生成图、五帧查错工程/ZIP和原视频仅在制作机器本地保留；新 checkout 不包含它们。范围见[本批 Git 与本地证据说明](../animation-platform-20261102.md#git-与本地证据)，真实视频提取目录 `video-jump-right/` 不受这些忽略规则影响。

## 朝向约定

本批按左右两个独立朝向制作，每个动作都分别检查，不能用一个方向代表完成。朝向以面罩和身体面对的方向判断，与世界坐标中的移动方向分开记录：朝右后退、朝右向左跳仍是右向动作。右手骨鸣器和左髋菌灯按角色自身的左右保持，不直接镜像另一套。

现有正式工程 [player_visual.gd](../../../game/src/player/player_visual.gd) 使用 `idle / run / jump / attack / heavy / hit / dash / heal` 八类状态；本次补制沿用这些状态，跳跃内部再区分上升、空中、下落和落地。当前 Godot 仍将同一批旧姿态负缩放为左向，并未加载本批左右候选；两套已有静态主参考也不能证明运行中已经有两套动作。

[原视频副本](../crab-animation-platform-v1/reference/user-crab-source-20261030.mp4)为 1520×608、24 FPS、30 秒。以下是从原背景联系图定位的**近似时间区间**，用于后续逐帧确认；还不是精确裁切表，也没有确认其中存在无掩挡的完整左向跑步循环。

## 为什么停止本轮图集生成

从 4 个相位扩为 16 格时，生成结果把本应抬膝的第 5、13 帧画回接触姿势，第 9 帧也缺少可靠的换腿身份，四行头盔大小出现变化。随后改成只在关键 1→5 之间补三个姿势，前两张有承重和收腿变化，但第 4 帧抬起的腿转成前景腿，接回终点 5 的远腿抬膝时会跳换。右向的定向修正进一步破坏了肢体连接。因此本轮不再用同类生成凑足 16 张。

这些限制属于当前生成结果的动作连续性，压缩、超分或播放成功不能修复。完整失败链见[左向 review.json](left-run/review.json)；右向三张图均保留在[候选目录](right-run/candidates/)，尤其 [run4-correction-rejected.png](right-run/candidates/run4-correction-rejected.png)明确拒绝使用。

## 跑动试制的检查

1. **已执行：** 静态检查左右参考及装备挂点；左向 v02 的四相位可读，右向三份与左向完整循环未通过。
2. **已执行：** 核对左向源图实际像素、RGBA、透明边缘和三列中间帧布局；只做显式裁片与统一尺度整理，没有按各帧外接框缩放。
3. **已执行：** 五帧局部候选通过真实 Framecraft API，627×627 缩至 470×470；输入 PNG 1,775,829 B，输出 1,015,041 B，减少 42.84%。这是缩小与边缘处理后的体积收益。
4. **已执行：** 平台保存、重开和 PNG ZIP 检查，保留 5 帧、30 FPS、工程单次播放；导出 `manifest.json` 仍固定 `loop:true`，单次覆盖值另存于[game-metadata.json](left-run/quarter-01/platform/game-metadata.json)。
5. **未执行：** 浏览器 UI 播放观察、完整循环与实速脚滑、转向/攻击/落地状态衔接、游戏回归和用户美术验收。工程可重开与静态逐帧检查不替代这些项目。

制作使用内置 imagegen 与现有 Framecraft 的处理/保存/导出能力。提示词与全部生成源保留，未另写修图算法；图像生成失败没有隐藏为“已优化”。
