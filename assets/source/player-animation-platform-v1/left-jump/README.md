# 朝左短跳：六关键姿势候选

这是根据拾潮者左向原图和原视频三个右向跳跃姿势补绘的短片，供检查朝向、身体弯伸和装备位置。**六个姿势已经可读，骨盆与脚的登记仍未解决；还不能用于游戏。** 在 Framecraft 选择本目录 `platform/projects/`，打开“拾潮者左向短跳_六关键姿势_未注册_v1”，即可查看原始与压缩结果。

工程文件位于 [2a85cb65e58a4b32882d66a5e519a388.framecraft](platform/projects/2a85cb65e58a4b32882d66a5e519a388.framecraft/project.json)。实际 UI 已验证单次播放到第 30 tick 停止、重播再次停止；原始/压缩同尺寸比较的透明显示正常，记录见 [ui-checks.json](review/ui-checks.json)。这只验证播放控制和一张准备姿势的透明比较，不代表脚不滑或动作已验收。

[快速动画预览](preview-unregistered.webp)由实际平台处理后的PNG无损编码为WebP，6个姿势持帧共750ms。预览文件重复播放方便查看，游戏动作仍为单次；它不是平台GIF导出，参数见[预览记录](review/preview-checks.json)。平台截图仅保留本地。

## 六个姿势来自哪里

[原生成图](jump6-v01.png)与[实际提示词](jump6.prompt.txt)保留。六相位为准备、蹬地伸展、上升收腿、空中前倾、着地深蹲、回弹恢复。**准备和恢复是补绘，六张并非全部逐帧取自原片。** 原片 190、209、228 帧约为 7.9167、8.7083、9.5 秒，只提供已离地、空中收腿、低姿落地三个动作依据。

实际送入生成器的三张动作参考保存在 [references/](references/)，角色主参考、参考用途及SHA记录于[来源清单](provenance.json)。

每帧保持左向：近侧右手握叉、左腰灯在远侧后腰并部分藏于短披风，红绳连接原肩扣和叉。未见右向失败稿中的手臂接成腿现象；第 4 帧披风展开幅度、第 6 帧回到原待机的衔接仍待美术复核。

## 裁片和透明处理

原图为 1536×1024。第 2 姿势脚尖和第 4 姿势披风越过名义上的 512 格线，因此使用显式非等大裁框，恢复完整轮廓后装入同一 640×640 画布；全段保持原像素倍率，没有按各帧轮廓缩放。裁框、放置偏移和未注册状态见 [crop-layout.json](crop-layout.json)。

源图大部分背景 alpha 为 0，另有低透明光晕。平台按透明阈值 8、soft/Lanczos、75% 比例处理为 480×480；没有再次 AI 抠图或手绘修改像素。六个姿势按 `[4,4,6,6,5,5]` tick 持帧，40 FPS，单次 0.75 秒；**30 个播放 tick 仍只有 6 个独立姿势**。0.75 秒是候选预览节奏，未声称等于原视频或游戏跳跃时长。

平台返回的 30 张 PNG 总量从 6,090,476 B 降至 3,244,368 B，减少 46.73%；这是缩小与透明处理后的结果。保存/重开、帧数和字节核对见 [platform-run.json](platform/review/platform-run.json)，实际 PNG 包见[平台导出](platform/exports/player-left-jump-sixposes-unregistered.zip)。导出 `loop:true` 为平台固定字段，单次覆盖值与 `pivot:null` 另记于 [game-metadata.json](platform/game-metadata.json)。

## 尺度和脚底仍有什么问题

在原图同倍率下比较两个稳定标记：头盔同部位横截宽为 `146/140/152/140/142/150 px`，相对第 1 帧约 −4.1%～+4.1%；叉头两骨叉的最大点距为 `83.01/81.15/85.91/81.02/82.42/83.87 px`，约 −2.4%～+3.5%。透视、颜色阈值和人工取点都有误差；这些结果支持“大致同尺度”，不能证明刚性尺寸完全一致。

640 画布上的骨盆中线人工估计为 `x=395/325/360/400/406/354`，误差约 10–15 px。若统一到 `x=384`，建议横移量为 `−11/+59/+24/−16/−22/+30 px`。接地的第 1、5、6 姿势，近脚接地点约为 `(405,564)/(336,529)/(399,540)`；仅统一脚底 y 就需要分别补 `0/+35/+24 px`。

问题在于两个条件不能同时满足：按骨盆横移后，近脚 x 约为 `394/314/429`，第 5→6 姿势相差约 115 px。按近脚横移则骨盆又明显移动。这组横移量只是定位问题的候选，不代表跳跃应该固定骨盆；落地应以真实支撑脚、身体前移和体重转移为依据。髋部遮挡与近/远脚判断仍有人工误差，下一次需把第 5→6 姿势的身体运动和双脚相对关系一起修绘，或补充有动作依据的过渡，不能靠平移达标。**本批保留未注册候选，没有把自动贴脚或只对齐骨盆称为完成。** 详细坐标、取点方法、原视频样例和当前游戏尺寸见 [anatomy-scale-root.json](review/anatomy-scale-root.json)。

本批没有改正式素材或游戏。左右朝向目前都有可检查的样稿，玩家完整动作集、足够补间、地面接触、状态衔接与用户美术认可仍未完成。
