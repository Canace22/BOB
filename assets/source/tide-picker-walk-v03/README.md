# 拾潮者 Walk V03

将本会话生成的走路视频接入 `godot/WhalebellyRuins` 的主关卡移动状态。用户最终明确要 Walk，不替换 Idle。12 FPS、7秒、84张256×320透明帧，公共锚点(128,300)，图集2048×3520。当前为已接入的视觉评审稿，保留源视频脚形漂移、局部边缘缺失、接缝及滑步限制，不标为用户美术签收。

## 来源与时长

- `source.mp4`：本会话 Seedance 2.0 图生视频的静音副本。任务 `vj_0f535bce-6ef0-45b1-a033-9c1925e52589`；角色原画由用户提供并授权本任务使用。原提示词在同一 Chaos 画布视频节点 `skills_v_0591d54c66`。
- 原始视频145帧、24 FPS，实际6.041667秒。用户要求不足一秒向上取整，因此目标为 `ceil(145/24)×12=84` 帧，共7秒。
- 为避免起步停姿和尾部近一秒冻结，运行循环选取源帧区间 `[22,142]（含两端）` 的两轮连续步态（5秒），均匀重定时到7秒，在84个输出时刻取源视频帧。**不是将整段视频原速直接抽成84帧，也不是增加11张AI原生帧。** `manifest.json`逐帧列出准确源帧号；84帧像素均不同，没有倒放。原片完整保留。
- 初版尾部光流闭合产生脚部重影，弃用；最终不使用光流合成的步态收尾帧。

## 图像处理

`build.py`以固定255×340视频坐标及统一缩放提取；连通域移除中性背景和手脚间孔洞。源片骨叉右侧被裁切，用完整原画的骨叉及测得刚性变换补回；披风左侧边缘按测得流场重投影。角色本体和迈步来自视频，未用静态图整体位移冒充走路。没有逐帧包围盒拉伸或把抬起的脚逐帧贴地。此版本依赖相邻 `tide-picker-idle-v03` 的完整原画与刚性估计函数。

## 游戏接入与验收

- 主入口 `scenes/main.tscn` → `CampaignPlayer.tscn` → `campaign_player.gd`，用 `campaign_walk_visual.gd` 显示走路；原状态名`run`保持兼容。独立技能Demo仍使用原动作库。
- 固定12 FPS，只有地面移动状态显示；实际位移为零时不推进，暂停/命中停顿随物理控制器暂停。停止恢复原待机，跳跃/攻击使用原动画与分层；朝向沿用原控制器整体翻转。
- 角色尺寸按当前房间的80–110像素目标等比换算，物理速度、碰撞、技能时序与存档接口保持。
- Godot4.7.2实际OpenGL回归：`tests/walk_animation.gd`。覆盖84帧/12FPS/7秒、透明边距、左右移动、停止、暂停恢复、跳跃、攻击、参考显示、顶墙、循环与换房。报告在 `evidence/walk-v03/checks.json`。
- 独立实机预览：`scenes/characters/walk_preview.tscn`，F6启动；空格暂停、右箭头逐帧、A/D朝向、1/2正常/慢放。两次循环录像：`review/walk-preview.mp4`；明暗底、实际尺寸与主关卡截图已由Agent检查，用户美术认可未获得。

## 限制与恢复

源视频腿部身份/蹼足体积及摆动并不完全稳定，手和道具仍有少量变形，裁切披风无法完全恢复。相位匹配不等于像素完美无缝。统一重定时后步态比原视频慢，固定12FPS并不匹配原265像素/秒角色速度，实战仍可见滑步；未改变用户的帧率要求或游戏手感来掩盖它。左向是整体镜像，未单绘非对称持物。技术回归通过不等于商业动画质量通过。

恢复旧移动外观只需移除 `campaign_player.gd` 的 `walk_visual`初始化和更新调用；旧动作资产、Idle和源视频未覆盖。复跑制作使用本机 `work/wan22-production/helpers/Scripts/python.exe build.py`，再用固定Godot执行`--editor --import`和上述测试。构建脚本覆盖本资产派生文件，手工修改前应另存版本。
