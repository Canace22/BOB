## 实际生成记录

工具为`chaos_canvas_skill/scripts/skills_v2.py`。用户先选MiniMax H3并确认两段各10秒、768P、参考图与无声；两次任务均返回`vendor_unavailable`，明确为MiniMax厂商账户余额不足。停止后由用户选择Wan 3.0，并再次明确确认720P方案；复用同一画布与原来的两个视频节点，没有新增重复视频节点或擅自重试。

当前画布在“游戏技术研发”项目，名为“血巢虾群攻击与受击”。[打开画布列表](https://tech.seasungame.com/gaiclient/renderer/#/drawing)，在列表中点击该名称。原画、单虾基准、完整动作设计与两份提示词均已上画布并连至视频。真实workflow／node／job ID、失败记录与成功URL见execution.json。

Wan 3.0实际输出均为1280×720、30fps、300帧；原文件容器约10.031秒且附带AAC轨道。`*-original.mp4`保留平台原件；交付的`*-wan-v1.mp4`仅移除音轨、copy视频流并faststart，变为精确10.000秒。`validate.py`核对完整解码、零音轨、尺寸帧数与视频流哈希相同；没有重编码画面、拼接补镜头或冒称模型原生无音轨。

## 当前可用与需收敛部分

技术：两视频完整解码、规格及无声副本通过；每0.5秒抽帧拼板已检查，浏览器两片实际起点播放与结束状态已验证。技术通过不等于美术通过。

攻击候选保留了原画风格、同种虾的暖红／珍珠腹节、水丝与双向群流，可作为运动与特效参考；生成过程没有精确遵循全部设计时标，不能直接当成既有AI的动作时长。

受击候选存在明显偏差：原画人物仍出现、约5秒后出现镜头跟随／场景变化、波纹范围偏大，所需“少量个体偏开—局部缺口—回流补位”不够清楚。此片**未通过固定镜头和局部反馈验收**，只供首轮审阅，不作可接入资源。没有为修正观感自动追加扣费生成。

若继续修正，优先准备无人物的干净场景参考，将一次局部受击作为更单纯的样板；保留原节点，按用户决定定向重做，完成后再考虑攻击中受击。此为下一步建议，尚未执行。
