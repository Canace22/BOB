# 拾潮者左向动画 v2

本目录提供 11 个游戏片段、38 张交付 PNG，统一 384×384、pivot `[192,342]`、显示比例 `0.275`。站姿约 240px，游戏中约 66px。新增姿势由内置 imagegen 绘制；注册、裁片和持帧整理不会制造新姿势。没有镜像右向角色，也没有继续抠原视频遮挡段。

[交付清单](delivery/manifest.json)供主任务复制到运行库；[目标游戏尺寸预览](previews/all-actions-game-scale.webp)包含全部片段。每个动作目录的 `platform/projects/` 保存 Framecraft 工程，当前有效 ID 见[工程清单](review/current-projects.json)。`platform/exports/` 是未经改写的平台 PNG ZIP。

## 根部、落脚与尺度

旧左跳第 5→6 姿势在对齐骨盆后，近脚仍差约 115px。本轮重绘了同一足迹上的深蹲、回弹和站姿，按近侧右脚踝和公共接地线注册。远脚踝残差约 1.6 输出像素，约 0.45 游戏像素；人工点位误差约 3 个源像素。没有按每帧 bbox 缩放或把披风最低点贴地。[脚与根记录](review/foot-root-checks.json)保存坐标、方法和限制。

跑步保持前后两腿身份，使用两张新绘中撑连接四个关键相位。帧时长为 `60/60/20/80/40/20ms`，两半步各 140ms。近、远支撑脚踝分别按 `abs(局部x变化) / 周期相位差 × 0.275` 得到约 64.0、59.5 世界像素步幅，取 61.7。两侧估计约有 7.3% 差别，包含足部滚动和人工髋轴判断误差；实际脚滑仍要在游戏移动、停止和受阻时检查，不能把公式当作自然运动证明。

每个生成批次使用统一缩放，依据原站姿及可比较的头盔尺度换算源分辨率，不逐帧归一化轮廓。头盔宽和镜片长轴的同倍率人工复核见 [尺度标记](review/scale-landmarks.json)。头部转动会改变二维投影，记录没有宣称所有局部比例完全一致。普通攻击为保护最远叉尖，两姿势共用的近踝位置比其他接地片段右移 2px（游戏 0.55px）；其余公共 pivot 不变。

冲刺首稿的刹车脚跨步过大，无法自然接回同一站姿，未交付该张。已单独重绘 `dash/source/recovery-v02.png`，保留近、远脚足迹。重击原图带一条不需要的黑色分格线，使用显式内容裁框避开；冲刺脚越过名义格线，也用显式裁框保留完整轮廓。见 [裁片记录](review/crop-layout.json)。

## Framecraft 与检查

处理使用现有平台 `POST /api/compression/frame`，100% 尺寸、透明阈值 8、锐化 0，保留 RGBA。工程通过平台自身 save/load 方法保存、重开，PNG 包由原 exportCompressionZip 生成；没有用替代算法冒充平台导出。每段 `platform/review/platform-run.json` 保存实际请求设置和字节校验。

平台压缩预览会把超过 60 FPS 的输入限制为 60。本轮曾生成的 run/land 100 FPS 工程已废弃；当前所有工程不超过 50 FPS，持帧精确展开，动作总时长与 delivery 一致。原平台 ZIP 的 `loop:true` 固定字段未改写；单次与循环以 `delivery/manifest.json` 为准。平台默认 pivot 不能代替这里的公共根部。

已执行：

1. 11 段 PNG 尺寸、Alpha、非空、画布边缘检查通过；没有肢体贴到边缘。
2. 11 个平台工程保存重开，顺序、FPS、持帧与处理字节一致。
3. 实际 ZIP 逐帧与处理结果逐字节一致，攻击区间落在正确帧边界。
4. 同倍率看落地足迹、跑步两半步腿身份、头盔/镜片尺度，并生成正常时序与目标游戏尺寸预览。
5. 主任务负责真实 Framecraft UI 和游戏按键验收；本目录脚本检查不代表用户美术认可。

完整机器记录见 [delivery-checks.json](review/delivery-checks.json)。`verify.py` 可重做交付核对；`assemble.py` 根据保留源裁片和人工注册数据重建姿势；`package_platform.py <clip...>` 只重打指定片段，并更新交付清单。首次打包需要本机 Framecraft 路径与服务，脚本顶部保留实际位置。

没有修改共享台账、正式游戏代码或运行目录，也没有在本子任务提交。需入库与仅本地文件见 [保留清单](review/retention.json)。`review/` 中 PNG/JPG 检查图仅作本地证据，不保证新 checkout 存在。
