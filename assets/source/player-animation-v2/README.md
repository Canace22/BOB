# 拾潮者左右动作 V2

本批分别绘制左右动作，先修根部、落脚与跑步换腿，再接入 Godot 独立母蟹训练场。右手共鸣器和左髋灯保持角色自身的挂点；两个方向不互相镜像。

## 坐标与播放

- 运行 PNG 为 384×384 RGBA，公共根 `(192,342)`，地面 `y=342`，游戏等比显示 `0.275`。站立高度约 240 源像素，即 66 世界像素。
- 每个方向包含 `idle/run/jump_rise/jump_fall/land/attack/attack2/heavy/hurt/dash/heal`。动作名称与真实状态对应；基础动作先进入本地检查，缺项不会用复制单张图冒充完成。
- 源图按头部、躯干与装备尺度检查，按骨盆及具名支撑脚注册。落地保持两脚的相对位置，保留膝盖和身体缓冲；不用逐帧包围盒归一化或最低像素贴地。
- `run.stridePixels` 是一个完整左右脚周期的世界距离。由支撑脚在角色局部坐标的位移和相位间隔测得，再在实际速度下复核。播放器按实际水平位移推进，停住或受阻时回到待机。
- 跳跃分上升、下降与落地，落地单次结束回待机。攻击图的 `activeWindowMs` 映射现有判定的前摇、有效与恢复时段；不改变伤害窗口。
- 按住方向落地直接接入跑步，只有站定落地才播放固定足迹缓冲。地面攻击前摇和有效段站稳，收招时允许移动并切回位移步态；空中移动与现有跳跃/冲刺取消窗口保持原规则。不能一边平移角色，一边长时间播放固定双脚的姿势。

## 文件与复跑

`left/`、`right/` 保留各自的主参考、生成提示词、原图、注册数据、Framecraft 工程及导出。`delivery/manifest.json` 与平层 PNG 是接入输入。重复持帧只表达停留时间，不计新姿势。

Framecraft 使用原尺寸、透明边缘阈值 8、锐化 0；运行帧来自实际处理结果。工程的时间线展开到不超过 60 FPS，避免平台压缩对比预览将更高帧率截为 60。游戏使用逐帧时长，不使用平台图集的默认 pivot 和循环标记。

在仓库根运行：

```sh
python3 assets/source/player-animation-v2/export_runtime.py
node tools/godot.mjs sync-art
node tools/godot.mjs check
node tools/godot.mjs test
```

导出脚本校验两向 11 组动作、正时长、步幅、尺寸、透明边距，复制到 `assets/runtime/sprites/tide-picker-animation-v2/`，生成实际加载的 `animations.json`。开发时 `--allow-partial` 只用于提早观察基础动作，不能作为完整交付验证。

## 验收范围

1. 两向独立纹理、装备挂点、公共根与实际显示尺寸。
2. 跑动开始、停止、撞墙与转向；两条腿交替承重，完整周期的脚滑。
3. 起跳、顶点、下落、落地缓冲与站稳的连续切换。
4. 普攻两段、重击、受击、冲刺与调息的进入、有效和退出。
5. 实际背景、透明边缘、最大姿势、暂停及重试。

计算检查、平台播放、游戏按键与用户美术认可分别记录。当前接入和线上版本以 [游戏进度](../../../game/progress.md) 为准；未通过的原稿与本地审图仅保留在本机。
