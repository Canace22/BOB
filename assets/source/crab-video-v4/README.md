# V4 母蟹视角统一与步态

针对 V3 从侧面待机突然切到正面横扫/冲撞/踏步/抖壳的问题，用 V3 已认可的 `01_idle/000` 作为统一身份和镜头主参考，内置 imagegen 重绘四组动作，每组十二帧。实际提示词（含安全边距修正）在 `prompts.json`；被替换的 V3 源仍保留。背景、单钳下砸、待机及退场本次不重画。

## 可复跑制作

1. `raw/` 保存接受的原始生成图，`references/idle-master.png` 为主参考。走路、冲撞和抖壳初稿格间距不足，重新请求更大透明间隔；没有用裁切隐藏贴边肢体。
2. 安装 Python 的 `opencv-python`、`numpy`，执行 `python measure-registration.py`，只测量并输出 `registration.json`，不改图。连通区域定位十二个主体，壳堆模板提供横向根位置，脚底使用逐帧实际支撑腿的底部。每个动作只有一个等比系数，不按每帧外接框拉伸。
3. 安装 Node 的 `sharp`，执行 `node export-runtime.cjs`，按测量结果裁切、等比缩放、原始 RGBA 字节复制打包到 `assets/runtime/sprites/crab-video-v4/`。输出四张 3584×1536 图集，每帧 896×512，根 `(512,448)`。48 帧全部检查画布边距和编码/解码字节一致性。
4. 仓库根执行 `node tools/godot.mjs sync-art`。游戏中按 `CrabPrototypeVisual.ACTION_PATHS` 选择 V3/V4 图集；Godot 导入 WebP 质量 0.88。

壳模板相关分数最低：横扫 0.903、冲撞 0.7259、走路 0.9139、抖壳 0.8419。它们是定位辅助分数，不是画面质量评分；低分冲撞姿态已结合实机截图检查。原始测量、比例及根位置均在 `registration.json`，输出检查见 `validation.json`。

## 玩法接入

| 资源 | 作用 |
| --- | --- |
| sweep | 侧向低扫，0–3 蓄力，4–7 命中，8–11 收钳 |
| charge | 侧向压低重心并踏步前冲，替换正面抬身素材；攻击窗口沿用原型 |
| walk | 前进步态，实际位移每 10 世界像素推进一帧，120 像素一循环 |
| phase | 同视角抖壳，继续配合独立飞壳特效 |

停住或被挡时不累计步程，重试会清空步程；时间流逝本身不推进脚步。保持三种伤害招式、生命值、碰撞与躲避窗口，未新增跳砸或吐球。

仍是重绘关键帧，纹理、腿部体积和个别收招有残余漂移，尚非原片逐帧还原。单钳下砸、退场保留 V3，动作之间尚需继续精修。实际检查与发布见 [game/progress.md](../../../game/progress.md)；UI 读招、真人难度和声音听感不由机器人通关证明。
