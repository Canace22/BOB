# 血巢虾群 · 攻击与受击实机接入 V6

2026-11-17。用户确认参照前轮视频继续优化游戏。应用Godot开发与场景动态流程；复用V5玻璃虾、水丝、库内soft-particle与bubble，不生成新图或新视频模型任务。

## 从视频选择什么

已查看[攻击／受击视频抽帧与来源](../bloodnest-combat-video-v1/README.md)。攻击视频的前后错位、松紧变化、水丝拖后可作运动参考；受击视频的大范围光圈、镜头跟随及场景变化不进入游戏。实际开发依据原1秒预警／1.5秒横穿／0.7秒收招，半血沿用原规则，不拿10秒视频片长决定AI时序。

| 元素 | 判断与依据 | 本轮实现 |
| --- | --- | --- |
| 攻击群体 | motion，视频可观察到前后排错位 | 前排先收束、后排略迟；三股开放水路的起止点错开，沿切线朝向，末段舒展 |
| 水丝 | motion，视频可观察到丝状尾迹 | 原6条位图流线拉成弧线，横穿时适度提亮；受击附近小幅弯折 |
| 局部受击 | motion，前轮方案是局部偏开而AI片未充分实现 | 最近6只可见虾偏开、壳缘点亮，约0.46秒回流；原44只实例保持 |
| 接触弧／光屑 | motion，需短促提示 | 复用水丝位图承载两条短弧，8个soft-particle固定池；无持续大光圈 |
| 背景／HUD／相机 | 保留，不跟随受击 | 没有新增抖动、全屏闪白或屏幕扭曲；暂停树冻结所有新表现 |

这是**位图＋程序驱动**的群体生物表现，不是逐帧动作或把MP4作为游戏动画播放。

## 接入边界

`KitEncounter.on_damaged()`仅多一条视觉通知。伤害、HP、判定、水道、授能、存档代码保持；冻结源码测试将该精确通知移除、将前轮视觉构造展开回历史文本，继续比较旧SHA，没有重置原基线。整个world运行表对a6c8b07的玩法合同仍通过。

当前伤害回调不提供精确碰撞点，故把玩家中心转为群体局部坐标、限制在判定附近，再选最近可见成员作为表现接触点。效果方向来自攻击来源侧；这不代表新做了逐像素碰撞／弱点。最近六只之外的38只继续沿相同水路游动。攻击中受击仅叠加表现，不加硬直、击退、停时或动作打断。

旧AI保留原flash计时兼容其它敌人；血巢视觉桥将本体整体色恢复到配方色，改由局部壳缘Shader反馈，避免整团闪白遮住透明质感。子件读同一个visual_clock，没有独立墙钟或积攒粒子。

## 已执行验证

1. 根`check`零错误（原5条长脚本提示），全部**139项单测通过**。新增受击6／38局部性、左右来源、回流、攻击不取消、固定池与暂停；旧攻击朝向检查改为允许沿弧线倾斜，仍禁止逆向并限制物理附近包络。
2. 当前真实关卡**23项GPU／Input专项通过**：定点攻击编舞与待机／横穿受击；HUD／背景采样保持；相机固定；HP／hurt_rect相同；局部Shader独立运动；真实受伤、攻击输入击败、视觉命中通知、授能存档、退场及原返回门。
3. 真实战斗先受击再无敌，验证流程与反馈触发，不代表真人难度验收。定点受击录像中的on_damaged为显式时钟夹具，不冒称自然攻击录像。
4. `verify.py`确认world玩法与基线相等，两个V5源图和512导出继续有效；未增改房间配置、地形碰撞或背景素材。
5. 本地录像／截图／日志在`game/build/qa/bloodnest-combat-v6/`。攻击定点录像20fps／6.1秒；受击定点录像30fps／4.2秒，其中横穿段仍为1.5秒，后续收招展示回流。真实Input与夹具分别记录。没有录制性能结论、Web导出或听音验收，音频Dummy；只写QA档，不改玩家真实进度。
