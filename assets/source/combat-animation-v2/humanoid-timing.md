# 人形敌人的蓄势与爆发节奏

泵庭执卫、封梁卫与老守护者改为缓慢蓄势、临出手短停、快速到位、带重量收招。只重排已有绘图的播放时间；不加伤害、不延长或缩短AI阶段，不改已经校准的比例，也没有增加绘图数量。

## 时间由真实执行阶段拥有

原先四张释放图平均分配在整个active阶段，例如封梁卫0.22秒有效期的第三张图到0.11秒才播放，但实际攻击在0.04秒开始检查命中，画面显得慢于判定。现在人形近战释放图按实际秒数取样：先快速过渡，封梁卫/老守护者在0.04秒到主要接触图，执卫在0.06秒到位，随后约45毫秒进入随势姿态。伤害时间没有移动。

准备六图的归一化起点为0、0.04、0.18、0.40、0.66、0.84：早些建立压重心的姿态，中段逐步加载，末端保留约16%的满蓄姿势。收招先跟随惯性，再慢些恢复。与原来整个动作匀速播放区分开。

`humanoid_timing.py`由register.py在合并/比例校准之后应用，共涉及三个profile的15个攻击/施法动作、61条身体或准备FX片段。默认at依旧是阶段进度；快速释放条目明确写`time_unit=seconds`与`reference_duration`。运行sample从Visual传入当前真实phase_duration，恢复实际阶段秒数，不另开时钟；reference_duration只供没有actor上下文的离线夹具使用。压力缩短有效期也不提前画出接触图，阶段结束时不为播完整图而延长控制。

## 分招保留的边界

- 封梁卫弧刃格挡保持原来的及时抬架，不跟攻击一起变慢；反击出刃采用快速释放。
- 水弹三连在实际0.04、0.26、0.48秒分别重新做一次短促推出。复播同四张图不算额外绘图；投射物仍只由原water执行器创建。
- 老守护者复制的active/recover和主角幻影时间轴保持原实现；只调复制前的施法准备。
- 撑跃的vault仍按真实空中过程播放。原数据在落地settle后又把active映射回腾空6–9，现改为落地准备保持11、真实地面攻击到压地12、随后恢复13–15；源第10张双脚仍悬空，不再用于已接地阶段。第11张脚底经逐像素复核在局部y=241，原行中位根为220，登记中仅将该帧pivot.y改为241，保持整套固定比例、PNG和物理根不变，不在空中预播压地动作。
- 红光、背囊黄色高亮、有限格挡、预输入、取消和所有敌人攻击频率保持原机制。
