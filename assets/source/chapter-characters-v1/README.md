## 只读呈现的边界

新模块位于 `game/src/prototypes/chapter_characters/`：`actor.gd`负责位图与等比落脚锚点，`bindings.gd`负责稳定章节/阶段ID位置表，`presentation.gd`只读已有阶段、flags和救援时间。没有独立 `_process`、动作执行器、碰撞体、事件、任务或存档写入。既有view的时钟只调用一次更新。

- 第一章在 `chapter_one/loop.gd`薄安装补巢者；读取既有 `loop.passage`，分别站在第一菌灯与安全菌灯旁，用真实 `ground_y`，与玩家目标点分开，不额外加居民或对白。
- 第二章把原三名圆圈住户换成3种轮廓，复用既有救援/离场时间与安全台路线。原三圆圈位置所有权见 `chapter_two/view.gd:94`；没有增加住户数量或护送机制。
- 第三章补巢者与两名住户站在既有520平台，泛称压瓣守卫在旧瓣旁650平台，仅事故已发生后显示；不让安全后的居民漂在无支撑空中。旧代理/事故状态见 `chapter_three/view.gd:26`。
- 第4–9、12章读 `flow.stage().id`、任务flags和观察时间放演员在原交谈/救援点旁，坐标与view同为未减offset的数据域，view本身已有 `-offset`，避免重复减原点。第10/11不装新NPC。
- 战斗身份一旦由 `encounter.enemy` 或 `retired_body`持有，新层同身份演员隐藏；`flow.gd:23`阶段入口与 `encounter.gd:99`战后身体已有唯一所有权，`encounter.gd:137`负责读档恢复，不重复生成Boss或死者。

所有新角色目前是静态姿态。按任务flag换工作位、随救援时间移动或画面中持工具，均不登记为行走、修巢、抬巢的正式逐帧动画。其余技能补帧由独立动作工作负责。
