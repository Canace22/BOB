# 16 格直接生成动画：跑动循环实验

2026-10-28。目标是验证并改进「角色参考 → 4×4 连续姿势 → 直接拆帧播放」的方法，不经过视频生成。用户指定 16 帧，本次不改成 8 帧，也不把 16 个动作状态当作一个动作的连续帧。

**当前结论：完成四轮探索和可复现对照，尚未得到可验收的跑动循环。** 首尾跳变、腿部相位与装备连续性仍需修正。所有产物是实验候选，未替换正式资源、未接入或发布游戏。

## 查看与复跑

在本目录启动任意静态服务器，打开 [compare.html](compare.html)。四版同步播放，支持 8/16/24 fps、暂停、逐帧、浅色背景，以及只播放 15→16→1→2 的接缝检查。[preview.html](preview.html) 保留初始 A 版。

~~~sh
node assets/source/tide-picker/run16-trial-v01/export-trials.mjs
~~~

从仓库根目录执行会重新导出四版的 64 张 PNG、各自的 animation.json 和 comparison.json。导出器只支持本实验实际使用的非交错 RGBA8 PNG，其他类型直接报错。无需图像第三方依赖。每张导出后解码并逐像素核对；源像素和透明通道保持不变，只向右/下补透明边到公共画布。

macOS 上可复建姿势引导图：

~~~sh
swift assets/source/tide-picker/run16-trial-v01/make-motion-guide.swift assets/source/tide-picker/run16-trial-v01/motion-guide.png
~~~

这张图是诊断与生成参考，不是正式美术。它用固定长度的腿段和错开半周期的足部轨迹表达支撑、回收与短暂腾空；没有经过专业动作或实机速度验收，不能据此宣称得到标准跑姿。

## 测量与证据边界

四张输出均为 1254×1254，而非请求的 2048×2048。按 round(n × 1254 / 4) 确定裁格边界，格子宽高为 313/314；导出统一 314×314，不逐帧缩放、不按最低像素贴地、不改变顺序。布局是否让每格包含完整身体仍需逐格复核，等分只是初始拆图方式。

| 版本 | 16→1 轮廓差 | 其他 15 对相邻帧平均轮廓差 | 触碰导出边缘的帧 |
| --- | --- | --- | --- |
| A | 50.65% | 29.37% | 13、14 |
| B | 50.81% | 25.99% | 1、5、6、9、10、13、14 |
| C | 49.56% | 31.78% | 1、2、3、5、6、9、10、11、12、13、14、15、16 |
| D | 39.92% | 27.44% | 13、14 |

数据来自 [comparison.json](comparison.json) 和各版 animation.json。轮廓差 = alpha>32 的两帧掩膜对称差 / 并集，使用原始格子坐标。它同时受排版偏移、姿势和比例变化影响，不是流畅度评分，不能证明正确步态。触边可能来自散点或邻格，也可能是裁肢，不能直接视为缺肢数量。

检查中发现 macOS sips 曾返回成功却让 A 第 13 帧保留整张图尺寸；已全部改用确定性解码/裁切/编码，并验证 64 张输出的尺寸与 RGBA 像素。这是工具导出错误，与生成姿势错误分开记录。

本轮已执行：

1. 四版共 64 帧的解码、314×314 尺寸、RGBA 裁切往返核对；通过。
2. 浏览器全部图片加载、播放索引推进、暂停不前进；通过。

## 本轮可以沉淀什么

1. **先固定输入与计数。** 明确是一个动作的 16 帧、4×4、行优先；保留用户指定的数量。帧数不等于动作设计完成。
2. **生成完立即播放。** 同时提供正常循环、慢速逐帧和接缝局部播放；不仅检查最后一帧，还检查中途相位是否跳跃。
3. **把问题分层。** 排版漂移用裁切/注册处理；画面缺少相位、换手和肢体错误回到绘制处理；不能靠调速、拉伸、倒放或复用首帧冒充修好。
4. **保留失败对照。** 本例整图编辑没有纠正步态；视觉姿势图也没有自动得到正确动作。这两条都只作为本次证据，不能推广成“必定失败”或“必定有效”。
5. **验收有效后再写成标准流程。** 当前可复用的是记录、拆帧和对照方式；生成配方仍属候选。

下一项明确待验证的实验：先让 1/5/9/13 四个关键姿势准确成立，再以认可的关键姿势为视觉约束生成最终 16 帧；将 15/16/1/2 作为同一局部修绘单元验证接缝。最终仍交付 16 帧，不改成八帧。应先处理姿势准确性，再研究定位与时序；不能宣称本轮已验证这个下一方案。
