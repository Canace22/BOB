## 本次处理

使用 soft/Lanczos、75% 比例、RGBA PNG、锐化 20、透明阈值 2。保留半透明边缘，去掉来源中 alpha 只有 1–2 的碎点。未使用调色板量化或 AI 平滑。

39 张 PNG 总量从 **7,412,143 B** 降至 **3,272,847 B**，减少 **55.84%**。这是缩小后的体积收益，不能叫原分辨率无损压缩。来源本身由约 324px 的生成图集单格重采样为 512px，现有纹理柔化和局部肢体变化仍然存在。

## 复用平台调用

```sh
node process.mjs <Framecraft仓库> <本次尺度修正版来源目录>
python3 verify.py
```

脚本调用已安装平台的压缩 API 和未修改的 TypeScript 工程/PNG 导出函数。Node 只接收平台生成的下载文件，没有复制压缩或导出算法；不会操作浏览器 UI。需要该平台已运行在 `127.0.0.1:8765`，并安装其既有 Node 依赖。压缩图集另由真实 UI 导出；脚本本身只生成 PNG 序列 ZIP，原始图集包仍保留。

其他动作可传第三个 JSON 配置文件，指定 `output`（独立输出目录）、`framesDirectory`（相对来源目录的 PNG 文件夹）、`fps`、`name`、`exportName`、`loop`、`pivot`（来源像素坐标）及 `direction`。`copySourceFrames:false` 可避免在工程外再复制源帧，仍会在 `.framecraft` 内保留制作输入，并记录原始路径和哈希。按文件名数字顺序导入，所有帧必须已有相同画布；不等时长应先按统一 FPS 展开持帧。没有提供根部时会记录为未知，不能直接接入。不要对源图所在目录设置相同输出路径。

每次运行会由平台创建一个新工程；不要把不同动作写入同一个输出目录。其他动作的角色比例、方向、相位和来源许可必须分别确认。

配置的 `settings` 可覆盖平台压缩参数，例如保留原生尺寸时使用 `scale:1`，按样例实际验证后调整 `alphaThreshold` 和 `sharpen`。各批次报告记录实际生效值；默认参数仍为本目录的75%/阈值2/锐化20。
