# 原视频重新抠图单帧试验

2026-11-02。结论：平台现有的纯色与 Luma 抠图不适合这段复杂背景视频，未用于九组正式输出，也未替换游戏资源。

本页链接的原视频、抽帧图和抠图 PNG 均为本地证据，不随 Git 入库；调用脚本、参数及检查报告保留。需要这些图时按记录的原视频来源复跑，详见[本批 Git 与本地证据说明](../../animation-platform-20261102.md#git-与本地证据)。

选择旧版 `08_retreat/000.png` 对应的原视频 24.5 秒、第 588 帧（从 0 计数）。旧版在这里丢失整个左钳；原视频中的左钳仍然可见，但和玩家、飞出的贝壳、地面相互遮挡。

## 实际调用

Framecraft 的视频抽帧、纯色和 Luma 在浏览器前端实现，没有对应 HTTP 路由。此次以 FFmpeg 解码视频、编码 PNG，直接调用当前平台 `src/lib/media.ts` 导出的 `chromaKeyPixels` 和 `lumaKeyPixels`；未改写算法、未调用模型、未下载模型。不是 UI 或 HTTP 导出。平台提交、源库 SHA-256、完整参数和输出校验值见 [platform-rekey-results.json](platform-rekey-results.json)。

复跑入口 [run-platform-rekey.mjs](run-platform-rekey.mjs) 接收三个参数：现有 Framecraft checkout、FFmpeg 可执行文件、旧版后退首帧 PNG。脚本使用平台已安装的 esbuild 直接导入其 TypeScript 源码；不需要添加平台依赖。

原视频保留于 [reference/user-crab-source-20261030.mp4](../reference/user-crab-source-20261030.mp4)。原帧是 [retreat-source-frame588.png](retreat-source-frame588.png)，旧透明帧副本是 [old-retreat-000-missing-claw.png](old-retreat-000-missing-claw.png)。原帧为 1520×608，旧帧为 896×512：两者不能凭显示宽度直接比较角色尺度。

## 四组已执行检查

1. 纯色容差 12、柔化 10，取色 `#426d6f`：左钳保留，背景与地形大量残留。
2. 纯色容差 25、柔化 15：青色背景更多变透明，但螃蟹暗部也被掏空；棕色地形、玩家和飞壳仍保留，不能直接用作角色。
3. 纯色容差 38、柔化 20：壳、身体与腿严重半透明，未解决同色背景分离。
4. Luma 黑场 0、白场 85、Gamma 0.55、强度 1.7、抠除黑底：复杂背景几乎完整保留。背景探针 Alpha 为 254，不能认为已经抠净。

`*-opaque-review.png` 仅将实际 RGBA 输出正常合成到灰底，便于观察透明洞；不作为新的处理结果。部分图像查看器显示全透明区域的底层 RGB，所以判断透明效果时需看灰底图和 Alpha。探针只是局部像素检查，不是完整轮廓验收。

原片与角色共享棕红、米色和暗部，纯色或亮度阈值不能可靠识别主体。再次处理旧透明帧也不能恢复已经变透明的左钳；需要适用的主体分割/人工蒙版修整和遮挡补绘。此次单帧未显示足够优势，故停止全量重抠，避免把新的缺损批量扩散到九组动作。

## 后续 BiRefNet Lite 实测

随后为平台建立独立 Python 环境与 8766 本地服务，复用已有 PyTorch 缓存，仅安装所需依赖与 [BiRefNet Lite 固定版本](https://huggingface.co/ZhengPeng7/BiRefNet_lite/tree/aa62cd87eafb9cc43056d08ef3615a14628b831d)。权重为 177,634,392 字节；未安装标准或 HR 模型。模型文件与工具环境保留在 Framecraft 安装目录，不放入 BOB。版本、SHA-256 与依赖见 [ai-runtime.json](ai-runtime.json)。原有 8765 服务和语音工程环境未修改。

用平台原有 `/api/models/prepare` 和 `/api/matte` 进行真实请求，`mode=birefnet`、`birefnet_variant=lite`、`device=cpu`、`spill=0`。调用入口是 [request-platform-ai.py](request-platform-ai.py)，每个 PNG 旁的 `.request.json` 保留原参数、响应头、输入/输出校验值与耗时。没有自行修改主体蒙版算法。

已执行结果：

| 输入 | 平台采样分辨率 | CPU 耗时 | 观察 |
| --- | ---: | ---: | --- |
| 第 588 帧整图 | 512 | 2.359 秒 | 左钳完整恢复，背景大幅去掉；玩家与飞壳仍并入主体 |
| 第 588 帧整图 | 768 | 3.640 秒 | 更多腿部保留；仍不是独立 Boss 帧，不批量应用到 360 帧 |
| 第 588 帧玩家接触区域 | 512 | 1.770 秒 | 输出全透明，拒绝 |
| 第 588 帧玩家接触区域 | 1024 | 7.784 秒 | 玩家可见，但夹带上方蟹钳，拒绝作为独立玩家 |
| 第 190 / 209 / 228 帧玩家跳跃区域 | 512 | 1.577 / 1.551 / 1.541 秒 | 头、披风、钩和腿均可读，背景基本去净；第 190 帧有极淡残边，待透明精度复核 |

三个跳跃样例分别来自 7.9167、8.7083、9.5 秒。输入是人工选定的 190×150 原生区域，只裁切，没有逐帧外接框归一化或放大；裁切记录见 [player-jump-rois.json](player-jump-rois.json)，实际 Alpha 检查见 [ai-sample-checks.json](ai-sample-checks.json)。模型内部的 512 / 1024 采样不是源素材分辨率；190×150 输出不能称为原生高清。三个样例仅说明无遮挡片段可以尝试提取玩家，尚未形成连续动作、统一根部、完成循环或接入游戏。

原背景联系图还显示以下**近似参考区间**，尚待逐帧确认边界：2.7–3.7 秒起跳避钳；4.4–6.7 秒挥钩/攻击；7.9–9.5 秒跳跃并落左平台；10.6–13.9 秒红绳摆荡；16.5–19.5 秒空中躲球/落壳；20.6–23.0 秒向左低身闪避；24.5–28 秒朝右接近或退步；29–30 秒朝右离开。摆荡不能当普通跳跃或冲刺，联系图也不足以证明已经找到无掩挡的左向跑步周期。

模型首次 Xet 下载长时间停在 0 字节；独立服务改用官方 `HF_HUB_DISABLE_XET=1` 后通过普通 HTTP 下载成功，没有更换模型。当前只验证 CPU，平台设备选择未支持 MPS。实际美术、连续播放和游戏验收仍未通过。
