# 拾潮者 Run V03（源视频 Run v2）

当前主关卡地面跑步使用本批透明逐帧动画。12 FPS、7秒、84张不同帧，256×336画布，公共锚点(128,300)，图集2048×3696。资产版本V03沿用角色生产编号；本次输入是用户最新大幅度Run v2视频，未使用被否定的Run v1。

## 来源与时长

- `source.mp4`是用户指定视频的完整静音副本，实际145帧、24 FPS、834×1112、6.041667秒；来源与原提示词保存在`generation.json`。任务`vj_42f4e2c7-74f6-4c66-b240-bbafcfa89564`，沿用用户角色及本会话生成授权，没有新增付费任务。
- 不满一秒算一秒：`ceil(145/24)×12=84`，播放7秒。完整源区间0..144按时间顺序均匀采样84个时刻，整体重定时到7秒。它比原片慢约14%，不是原速抽帧后冻结尾帧，也没有补造AI动作。每个输出的源帧号、源文件SHA256与实际唯一帧数在运行`manifest.json`。
- 所有帧固定缩放、固定地面与锚点，保留原片腾空起伏。源坐标255×340下地面y=309，统一转到游戏锚点附近；不按逐帧包围盒缩放，也不把腾空脚逐帧贴地。

## 制作与运行

`build.py`使用OpenCV解码、SciPy连通域与Pillow打包。去除米灰背景及其阴影，保留较亮的骨叉高光，统一输出透明PNG。角色肢体全部来自视频，没有套用旧Walk的光流补叉和披风重投影。该源视频道具旋转更大，旧硬编码蒙版不适用。

主入口`scenes/main.tscn` → `CampaignPlayer.tscn` → `campaign_player.gd`；`campaign_run_visual.gd`在地面run状态显示本资源，原来的Walk资源与预览保留。固定12FPS，仅有实际水平位移时推进；暂停与顶墙时冻结。停止恢复原Idle，跳跃、攻击、技能继续使用原动作。未修改265像素/秒速度、碰撞、能力或存档格式。左向沿用整体镜像。

独立查看`scenes/characters/run_preview.tscn`，F6运行：空格暂停、右箭头逐帧、A/D朝向、1/2正常与慢放。`review/run-preview.mp4`为真实Godot GPU的两轮循环录像，340帧/24FPS，14.17秒。24FPS是录像采集频率，角色帧率仍为12FPS。

## 验收与限制

Godot4.7.2 Compatibility / RTX5060实际导入并执行`tests/run_animation.gd`：16项全部通过。包含84帧/12FPS/7秒、透明边距、左右移动、停止、暂停恢复、跳跃、攻击、参考显示、顶墙、循环和换房。JSON与左右实机截图在`evidence/run-v03/`。历史Walk测试改为显式装载保留资源，16项再次通过，不再要求生产默认选择Walk。测试使用隔离QA模式，不改用户真实存档。

Agent检查透明接触表、明暗底GPU截图、录像相邻姿势和循环接缝抽帧以及主关卡左右画面。技术接入通过，视觉保持candidate，未声称用户美术签收：原片披风、脚尖、骨叉有裁切，持叉与肢体存在漂移，接缝有姿势变化。透明留白没有补回裁掉的像素。固定12FPS与物理速度不严格匹配，仍可能滑步；不以改变游戏手感掩盖来源问题。

重跑：在仓库根目录用支持OpenCV、NumPy、Pillow、SciPy的Python执行本目录`build.py`，再用固定Godot执行`--editor --import`、`--script res://tests/run_animation.gd`。测试成功后`register.py`更新台账。运行文件由构建覆盖；手绘返修前另存版本。恢复Walk时将CampaignPlayer加载脚本切回`campaign_walk_visual.gd`，无需删除新资产。
