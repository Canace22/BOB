# 连续世界接缝联合补绘 V1

2026-11-16。本批针对用户反馈“背景与路径明显拼接”，将18条流式连接的通用蓝底/细橙台替换为与两端同坐标联合补绘的连续地形、远景和骨/膜根。它是实际游戏接入，不是概念图；整体审美仍待用户试玩确认。

## 来源与产物

- `inputs/`：从当前Godot渲染的两房同坐标参考，隐藏HUD/主角/敌人并叠实际路线绿线；保留真实房间比例与世界落点。不可用AI重新解释全图布局。
- `prompts/`：每个ID的英文内置ImageGen提示词及局部清理提示词。
- `originals/`：18张联合母版、4张去新跳台深景、2张透明承重台根；含候选/失败对照，不覆盖原房素材。
- `registration.json`：世界矩形、参考像素脚线、两端房序号、最终图片尺寸和SHA256。它同时同步到runtime/game目录。
- `layers.json`：实际使用的分层及复用台件哈希。子批次production-*.json与本机game/build/*delivery.json保留生成返回路径/实际轮次；提示词和图像均在项目内可追溯。
- 运行导出：`assets/runtime/sprites/seamless-continuity-v1/`；游戏副本：`game/art/seamless-continuity-v1/`，清单为game/art/manifest.json。共25张运行位图及1个注册JSON，原文件仅复制，不作非等比缩放或拉长。

本批全部新绘通过内置ImageGen，参考引导重绘不宣称像素级保真。原房内部核心仍由原图负责，生成件仅接管实际边界的重叠区域。已有E35独立台件另作注册/失败对照，来源为assets/runtime/scenes/xumen-vertical-v1/E35-ledge-1.png，不是本批新绘。

## 制作合同

水平路：完整骨/膜路基顶缘按参考实际脚线，承重下缘、孔骨根、光色与远处器官一起连贯，不再让一串小台代表完整岸线。跨胃/肺/脊/耳/尾连接保留两端的材质变化，但通过同一器官形体与背景尺度过渡。

竖井：完整生成母版曾遗漏/偏移跳台，因此最终将4张竖井拆为“无新跳台的连续骨/膜深景＋精确定位独立悬臂台根”。不通过扩大容差掩盖悬空。水平转折岸线保留在depth里；独立台根只放在非水平接段的中间阶位，脚线仍由现有碰撞决定。

- 口腔骨根：1536×1024，接触段x110..690、y267；按580px接触宽等比缩到140px，以(400,267)居中注册。根部向相邻竖阶/中央脊侧镜像，保持轮廓比例。
- 肺膜根：1536×1024，接触段约x100..600、y250；按500px接触宽缩到140px，锚点(350,250)。
- 所有根保留RGBA原字节，原始低Alpha噪点与可见轮廓分开统计；运行开启mipmaps与线性过滤，采用轻度冷暗调制匹配背景，不把贴图改为程序几何。

静动判断：新路基、洞壁、深景与台根都是静态解剖结构；不新增生物，不登记逐帧动作。原房内部鱼群、垂须、气泡和机关沿用，不为了接缝补绘重做。原房核心、能力条件、连通、碰撞、主角动作与存档合同保留。

## 引擎所有权

`seam_art.gd`按世界矩形等比定位；`seam_art.gdshader`只取边界重叠区域，并保护不属于该边的其它房间核心。原静态层使用同一块接缝所有权遮罩退出，避免新路基叠在原图前景上产生黑三角/重影。绘画层在主角后，不改变主角/敌人实例。不是对整个画面加模糊，也不是继续扩大整房透明边。

修正了continuous_depth与seam_mask原有的世界/房内坐标假设，并对齐已加载邻房与活动房的视差位移，避免跨界时接缝图层跳动。

## 已验证与限制

- 原生18边双向输入73项通过；不按E、不淡黑、同角色、路线保持。每条仅起点使用夹具，后续真实InputEventKey；不冒充从开局自然通关。
- 注册/纵横比例、分层、材质所有权、独立台、原玩法/存档正式套件112项通过。根目录check/test另受已有未跟踪章节原型缺图阻塞，不能写全工程通过。
- 原生每条入口/中央/出口共54个机位渲染，图在game/build/qa/seamless-art/；已检查水平路、跨区、U形支路、胃肺及尾槽竖井。静态机位只证明画面，不代替真实按键回归。
- 资源审计missing=[]，哈希/来源/同步登记齐全。新增运行图约50MiB级，未重导Web；本轮没有发布、提交或推送。
- 本轮是AI技术/视觉复核，用户整体审美未确认。生成外侧纹理与原图不是逐像素一致；引擎仅取边界区和受控重叠，保留原房核心。原始世界背景细节在长竖井放大后比房内略软，后续若用户要求同级近景细节，应针对同坐标局部补高分辨率，不能非等比拉伸。

最终复跑入口与结果见game/progress.md；用户认可、静态补绘、运行接入及路线验收分别记录。
