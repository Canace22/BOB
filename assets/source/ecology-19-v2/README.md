# 当前19房环境适配生态 V2

本批修正上一轮“概念图里有生态、普通游玩镜头里不一定看见”的问题。生态现在写入当前19个房间的场景 `.tscn`，每个场景拥有唯一的 `RoomEcology` 节点和稳定 `room_id`；单独加载场景、流式跨房和正常跟随镜头都走同一套接入。

## 按环境使用的素材

| 环境 | 使用的生态 | 接入取舍 |
| --- | --- | --- |
| 须门遗港 | 现有暖色菌床、须筛小鱼、窄域逸泡 | 贴近平台边缘和须筛后方，主跳跃线留空 |
| 肺心潮庭 | 现有珠菌、端足群、冷色逸泡 | 沿膜边和两层水道分布，血巢战斗区降低密度 |
| 胃枢 | 暖色菌床、营养微粒、稀疏小鱼 | 靠近营地和胃枢营养流，不覆盖壳巢 |
| 断脊 | 新的暗红骨孔附生穗透明位图、紫色贝床、稀疏鱼 | 遵循象牙骨、红色附生物和贝床材质，不使用肺心粉色珠菌 |
| 耳海 | 新的灰白/淡蓝管状小群落、微粒 | 低亮、低密度，三槽记忆和缄声覆膜保持安静 |
| 归海释放槽 | 原有归海幼体、外海鱼和微泡 | 生态顺着幼体外游方向，不增加新门或新结局 |

两件新位图：`images/r4-attached-colony-clean.png`、`images/r5-attached-colony-clean.png`，运行副本位于 `assets/runtime/sprites/ecology-19-v2/` 并同步到 `game/art/ecology-19-v2/`。它们是独立透明候选，根点、可见宽度和 SHA 记录在 `assets.json`；程序只驱动末梢轻微摆动，根部保持固定。生成输出仍标为候选，用户整体美术审阅与签收单独记录。

每个房间的完整生态组合记录在 `ecology-design.json` 和运行配方的 `ecology_design` 字段：远景、 中景、前景三层分别定义鱼/端足、浮游微粒与气泡/附生物的职责。R1 使用场景内已有鱼群，避免重复生成；R2-01 保持端足育床，R2-04 保持虾群战斗留白；R3 使用营养微粒和慢鱼；R4 使用骨孔鱼影、沉屑、暗红附生穗；R5-01/R5-04 不放鱼，只保留安静微粒和气泡；R5-08 与已有归海幼体同向迁游。

## 运行契约

`RoomEcology` 在场景树中负责自己的有限池，不写碰撞、能力、存档、敌人或奖励。主控的 support 阶段只为旧测试夹具补建缺失节点，不会在已接入场景重复创建。`ecology-19.json` 的 `colony` 字段指定房间对应素材、可见宽度、根点、摆幅和微光强度；附生位置按已有曲面插值，不创建新平台或柱块。

## 验证

`game/build/qa/ecology-in-scene-v2/` 保存当前实机场景的普通跟随截图、全景图、日志和资源审计。最终结果：288 项自动测试通过、252 项环境专项通过、19 房普通游玩镜头均有生态像素贡献并可运动，18 条世界连接双向按键通路通过，资源审计 `missing=[]`。现有编辑器/游戏窗口不会热加载新场景，需重新运行工程才能看到本批内容。
