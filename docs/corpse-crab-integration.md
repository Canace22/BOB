# 尸蟹：普通敌人的动作与战斗接入

尸蟹在须筛 R1-02 一只、舌台 R1-03 两只，沿用三个出生点和HP3。正式 `main.tscn` 通过敌人稳定类型 `corpse-crab` 实例化 `CampaignCorpseCrab`，隐藏对应旧静态 EnemyArt；唯一伤害接收者接入既有 `damage_enemy`、回魂、弹体和近战接口。门庭母蟹Boss独立保留，普通尸蟹死亡不会解锁冲刺或写入Boss击败标记。

## 美术与动作合同

来源、提示词、裁片参数和重建脚本见[制作合同](../assets/source/corpse-crab-actions-v1/README.md)。3张AI姿势表共24个原始姿势，生成工具未暴露模型版本；不是视频提帧或高帧率手绘动画。近侧大钳负责举钳和低扫，远侧小钳保持独立。朝左母版整身镜像到右侧，视觉根只翻转一次，攻击矩形读取同一facing。

| 状态 | 图集帧 | 驱动 | 已验证范围 |
|---|---|---|---|
| idle | life 0,1,2,3,2,1 | 5fps循环 | 双向GPU姿势与实机待机 |
| walk | walk 0–7 | 实际移动40px一循环 | 双向GPU，实机追近；停止不踏步 |
| tell | attack 0–2 | 0.70s，固定朝向 | 双向实机举钳、单元测试中断 |
| active | attack 3–5 | 0.20s；0.06s扫击 | 双向实机攻击；跨帧事件、前/后/跳过测试 |
| recover | attack 6–7 | 1.10s，第一帧0.14s | 双向GPU、实机反击窗口 |
| hurt | life 4–5 | 0.22s | 双向GPU、实际J攻击；旧攻击事件清理 |
| dead | life 5–7 | 0.50s倒下，1.2s开始淡出，1.8s隐去 | 双向GPU、实机击杀；立即清除伤害与碰撞 |

帧画布256²，脚底锚点(144,224)，显示比例0.82。3张1024×512透明图集合计1,364,328字节，基础RGBA约6MiB；独立序列供编辑，运行仅加载3张图集。复用已有 `crab_video/impact_dust.png` 作为低扫触地点尘效，不重复生成或叠加本体钳光。姿势为有限帧保持式动画，步足幅度较小，未宣称电影级连续运动；用户审美认可尚未取得。

## 行为、操作与范围

巡逻28px/s、追近45px/s；出生点左右110px活动限制和前方地面探测防止自行掉离平台。进入水平110px、垂直78px以内预备低扫；低扫仅伤前方96×32px矩形，造成1伤害并检查墙体阻挡。每次攻击一个实例，只触发一次；跳起可越过低扫，预备和收招可反击。死亡立即解除碰撞，切房随World回收，重进房间按原普通敌人规则复活。

`A/D`移动，`空格/K`跳跃，`J/Q`普攻，`U`弹体，`E`过门，`Esc`暂停，死亡界面`R`复活。试玩可从外伤坡沿正式出口进入须筛；已有数字`2`/`3`房间预览用于快速检查，无需解锁新技能。键盘自动验收用`2`选择起始房间，随后真实步行到右侧门并按E进入舌台；不把预览夹具描述成开局连续通关。

代码入口：`game/src/campaign/enemies/corpse_crab.gd`负责物理和状态，`corpse_crab_visual.gd`负责呈现；源元数据 `animations.json` 记录帧序/事件。时长常量需与元数据同步。没有新增玩家控制器、存档字段或36键输入系统。

## 复跑与证据

在仓库根执行：

```sh
python assets/source/corpse-crab-actions-v1/build.py
python assets/source/corpse-crab-actions-v1/register.py
node tools/godot.mjs sync-art
node tools/godot.mjs check
node tools/godot.mjs test
node tools/godot.mjs export-web
node game/tests/serve_web.mjs
node game/tests/web_corpse_crab.mjs
```

构建依赖Pillow、NumPy。浏览器脚本支持`PLAYWRIGHT_MODULE`、`CHROME_PATH`、`GAME_URL`、`TEST_OUTPUT`；默认本批4199端口，启动服务前设置环境变量`PORT=4199`（PowerShell：`$env:PORT='4199'`）。`RECORD_BROWSER=1`额外保存浏览器原始录像，报告中的`gameplayStartMs`标记下载结束时刻；canvas录像可能漏掉浏览器没有呈现的等待时段，不能用它推算墙钟时长。所有证据留在忽略目录 `game/build/qa/corpse-crab/`。

- 单元回归：57项通过，新增5项覆盖点位/唯一伤害接收者、跨时点低扫、实际玩家命中去重、弹体死亡与重进、距离帧及单次镜像；包含既有母蟹回归。
- GPU双向覆盖：`native/coverage.json`和`native/pose-fixture.mp4`；七状态左右共14行。该录像是正式场景状态夹具，不冒充自然战斗。
- 实际输入：`web-v4/report.json`，12项全部通过，浏览器/引擎错误为空；`尸蟹_主场景键盘实测.mp4`展示左右读招、受击、击杀、切房、玩家死亡复活。使用独立浏览器上下文，不改用户存档。
- 公网复核：`online/report.json`同样12项通过，首次就绪132.537秒；发布与源码绑定见[进度](../game/progress.md)。`尸蟹_线上实机验收.mp4`从浏览器原录像只去掉下载等待，未加速战斗时间轴。
- 查看了透明边明暗底、接地与正式尺寸、左右大钳预备/低扫、死亡收拢姿势。技术/AI视觉复核通过，未代替用户美术签收。未新增移动触屏或声音听感验收。

## 性能边界

Godot4.7.2 Compatibility、NVIDIA RTX5060、1280×720、60fps限帧。相同R1-02/03出生点夹具，各预热120帧、采样240帧；不录屏。基线只恢复父版本main.gd的普通敌人接入，测量完恢复本批文件；不触及用户原工作区。脚本 `tests/whalebelly/corpse_crab_benchmark.gd` 可重跑，资源/冷却覆盖仅用于压力夹具。
