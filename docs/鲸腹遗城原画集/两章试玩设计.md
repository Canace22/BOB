# 第一、二章试玩

本版用四个房间检验“探索—短战—休整—Boss—战后事件”是否有趣。叙事依据用户提供的[世界观与人物设定](世界观与人物设定初稿.md)和[主线初稿](主线叙事初稿.md)，两份原稿保留草案状态。在线入口见[项目首页](../../README.md)，验收证据见[工程进度](../../game/progress.md)。

## 可玩路线

| 房间 | 玩家做什么 | 承接 |
| --- | --- | --- |
| N01-A 须庭入口 | 学习长短跳，跨越断口；高处可听旧骨回声 | 追歌进入遗城 |
| N01-B 须庭内侧 | 借三处高台接近或绕开扑咬，清开两只食腐甲，再找补巢者 | 补巢者指向折井 |
| N02-A 折井上层 | 沿四段膜褶台地下行，高台取回声、右侧放下返回短桥 | 看见维护通道和封锁设施 |
| N02-B 封锁口 | 完成拒绝通行对白，直接进入原母蟹竞技场；跳低扫、撤离下砸/冲撞，抓整套收招反击 | 胜利按 Enter 回到住巢旁，继续救援 |

每个房间入口可休息并保存。失足在安全位置恢复，战死回最近营地；已找到的回声、清开的短战和壳闩保留。Boss 失败重来时恢复生命，通关后守卫以非敌对状态留在场内。两处回声为可选收集，不阻断主线。本版没有冲刺门槛，也不授予新叙事尚未确定的能力奖励。

## 交付边界

运行能力包括四房连接、章节交互、阅读暂停、近战短战、非致死 Boss 结果、地图、营地、死亡恢复、独立续档和重开。与正式主线、母蟹训练场分别保留入口。

第一版复用场景和静态敌人的做法被用户否定，11 月 2 日重绘了环境、敌人和居民。当前保留四房叙事骨架与补巢者编织姿势，封锁口改用用户指定的母蟹战，受挫后停战。老守护者用四个支撑姿势接住并托回住巢，随后对白收束；住巢移动由程序控制，属于短演出，不是全逐帧剧情短片。

四房重新编排，以专属须庭远景和食道膜褶远景区分章节，骨壳地形、支撑、门、灯与住巢使用同批 2D 位图。玩家保留已有两向动作，食腐甲有行走/扑咬；上一批守卫 40 个姿势保留为制作历史。来源见[守卫制作记录](../../assets/source/chapter-guard-v2/README.md)、[环境与居民记录](../../assets/source/chapter-world-v2/README.md)、[运行清单](../../game/art/manifest.json)及[台账](../../assets/catalog.md)。

2026-11-03 用户确认接入“带蓄力远程、护盾和三阶段连招的母蟹训练场”。当前章节实际战斗直接复用该版场景、AI、动作和反馈，上一批新负壳守卫及 40 个姿势保留作制作历史，已退出章节运行路线。母蟹承担本次封锁口对抗的角色，非致死结束后继续救援。用户原始叙事草案保留，不回写原稿。

母蟹三阶段连招、护壳、重击打断及远程详见[原战斗方案](母蟹Boss战原型.md)。章节全程 6 格生命、U 蓄力和护盾；开战与重试按原战斗恢复初始资源。胜利先保存，再由 Enter 返回章节；战中刷新回封锁口营地，胜利界面刷新回住巢旁。旧版回声和壳闩保留，原守卫完成标记不计为母蟹胜利。测试能证明路线可完成，纯视觉读招与主观难度仍需用户试玩。

## 开发与验收

原生运行：`node tools/godot.mjs run -- -- --chapters`。浏览器开发版在常规导出 URL 后加 `?chapters=1`；发布命令为 `node tools/deploy-pages.mjs --chapters`，目标为 `/godot-chapters/`。独立存档 `chapters-v1.json`，暂停菜单重新开始只清本试玩。

1. 工程检查与 headless 测试：场景引用、四房入口、字体字形；存档隔离、重开、战后守卫和叙事门槛。
2. 真实键盘四房路线：平台可达、两只必经食腐甲、补巢者互动、Boss 与结尾。
3. Boss 生命周期：战前交流、母蟹死亡重试、战中/胜利界面刷新、取胜后继续救巢。
4. 地图与阅读暂停、刷新续档、已完成状态保留；既有主线档保持不变。
5. 实际截图复核中文、角色接地、位图加载与遮挡；两处可选回声和短桥独立复核。

实际执行结果记录到工程进度。自动战斗按键会读取状态判断时机，能证明规则可完成，主观手感与纯视觉读招仍需要玩家反馈。
