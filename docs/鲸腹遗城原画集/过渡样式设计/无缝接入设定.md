# 须门遗港：无缝接入设定 V1

本轮交付设计与制作合同。**现有物理连通保留，新过渡样式尚未接入、运行验证或发布。** 不把上轮工作区中的三个Shader实验当作已通过方案。

## 一、确定采用的形式

接头必须成为一段完整地形，而不是两张房间画之间加一张桥。制作顺序为：**固定两端坐标 → 同时画A房尾部、连接带、B房头部 → 拆层 → 清掉旧图重复部分 → 同镜头重构 → 动态与实机验收。**

- T01颌骨斜拱用于E01：同一段下颌骨路，斜骨拱把上方结构联系起来，开放水域贯通。
- T02骨膜渐变分成三个专用变体：E02从须筛到舌台，鲸须变疏、舌膜增加；E03到母蟹区域，骨质支撑增厚但不提前泄露Boss；E04进入喉膜育窝，组织褶皱加密、空间收窄。三条边共用设计语言，不能共用同一张完整背景。
- T03骨壁生台分别适配E33和E35。E33先向左绕到上行轴再向右接入；E35沿右侧轴上升后进入记忆袋。骨壁支撑位于中景，台面位于可玩层，保留原单向平台与下行方式。

这里的“无缝”同时指：地形可行走，视觉不露接边，镜头不瞬移，动件相位不重置，状态不重复生成。设计允许房间ID改变，但玩家不应感到图片和角色被换了一次。

### E01先锁定的制作框

- 核心可走段X1645…2209，脚底Y631.847。
- **建议联合重绘范围X1389…2465，宽1076px**：向两侧各侵入256px，作为雕出自然接合轮廓和纹理的范围，不是额外玩法地图。
- **建议工作画布世界范围X845…3009，Y-264.153…1271.847，共2164×1536px**：包含核心段与镜头扫视余量。画布原点明确保存在元数据，不从透明包围框猜。
- 以上256/800px余量是本项目起始规格，尚未实机验证。要根据角色位置、镜头前视、冲刺缩放、设备画幅和各层视差取可见范围并集；不足就扩画，不拉伸。
- 当前角色碰撞28×65px。站立通道拟留至少97px净空；预期需要完整起跳的局部拟留约240px视觉净空，但必须按实际跳跃轨迹和原房目标确认，不把全段强制改成同一高度。
- 所有看似能踩的明亮台面要么对齐原碰撞，要么明显放在低对比远景；禁止新增一个“看起来能站、实际会掉”的假平台。

## 三、为什么当前接头不自然，怎样修

### 1. 房间A、过渡带、房间B必须联合绘制

拿两侧真实截图及原分层源图，在同一世界坐标母版中摆放。先画完整的骨质承重结构和路面，再决定素材分界；不能先裁一根方桥再用透明渐变处理边缘。新骨路应延续两边已有骨纹方向、孔洞尺度与组织厚度。

替换区域用可编辑选区明确标出。新骨拱/地面已占有的像素，旧图对应像素必须移除；旧路留下的墙脚、黑底、装饰或蓝水矩形不能继续叠在下面。遮挡后露出的区域需要补绘背景。任何位置只有一个主路面来源。

### 2. 不用全局按蓝色抠背景

旧图的远景水色可能烘焙在道路、洞壁、前景碎片中。按蓝色自动抠像会一起抠掉青色植物、鱼群和暗部，不作为正式方案。先在原像素上制作人工可编辑遮罩，逐件保留骨、附生物与光效；局部自动选色只能辅助，必须检查残留与误删。

工作区此前的颜色键Shader仅为未通过实验。正式选项优先是离线可编辑蒙版、补绘和独立运行PNG；局部Alpha柔边只负责消除少量边缘，不承担结构重画。

### 3. 避免前景做“遮羞板”

骨拱与柱脚首先在中景接成完整轮廓。近景暗珊瑚可包住地面底缘、视野外角和结构后侧，但不得横跨整条接合线遮挡脚底。**关闭前景和雾层后，地形仍需自然相接。**

支路中景支撑要绕过攀升走廊，或明确处于玩家后方；不可把没有碰撞的粗横梁画成玩家必经的实墙。起跳端和回程落点始终可见。

## 四、分层资产合同

| 层 / 稳定命名 | 内容 | 与接缝有关的固定约束 |
| --- | --- | --- |
| `R1-DEPTH-*` | 共用远景水域、远处骨架、补绘隐藏面 | 使用世界锚点；共同地标位置不因激活房间重置；按空间制作多个有叠接的专用片，不拉长单幅图覆盖整章 |
| `E01-MID-ARCH-*` | 斜向颌骨、上方组织、附生物 | 根部接到真实支撑；两侧骨纹和光向连续，留出站立/跳跃净空 |
| `E01-WORLD-GROUND-*` | 与原顶面一致的新骨路、下部承重 | 脚底锚点、轮廓路径与原碰撞匹配；纹理有连续走向，不平铺明显重复块 |
| `E01-FRONT-*` | 下缘近景、角落框景 | 独立PNG；重叠片视差一致；不可盖掉路线或用黑带强行挡接头 |
| `E01-FLEX-*` | 独立鲸须、植物和附着纤维 | 静态底图清掉同一动件副本；根部固定、细丝末端延迟；刚性骨路不变形 |
| `E01-FISH-*` | 独立游泳图集与路径 | 身体动画与空间路径分开，跨带不重生/换相位，不烘焙进静态图 |
| `E01-BUBBLE-*` | 分区源、粒子池及柔边消失区 | 预热分布、有界回收、生命周期保持；透明边不在画布矩形上显现 |
| `E01-LIGHT-*` | 独立光域/遮罩、菌灯 | 光向和静态高光连续；明度变化克制；灯是封闭菌灯，不出现裸火 |

实际件数以逐边元素表为准，以上是命名家族，不是宣称每一类都已生成。已有合格鱼、气泡、垂须可复用，但参数需按新的空间样板复验。

每件记录：ID、来源、母版、原始画布、透明余量、导出尺寸、每像素世界比例、世界锚点、根线/脚底线、图层、视差权重、静动类别、原图副本清理范围、实际节点、碰撞/交互适用项和验收证据。静态结构的运动/声音不适用时说明理由，不强制所有装饰运动。

原件、分层母版与运行件分别保存。新制作目录按边/版本组织；原件不覆盖，保留OpenRaster或Krita母版及遮罩、导出脚本/清单。新素材完成入库、manifest同步后再由场景引用。

## 五、Godot接入结构

以下是拟定结构，不是已存在节点：

```text
ChapterPersistent
├─ SharedDepth                 # 只拥有远景与共同地标
├─ Transition_E01              # 边ID稳定，世界锚点固定
│  ├─ Middle                   # 骨拱、柔性根部及纤维
│  ├─ PlayableArt              # 只挂位图，不另造一份重复碰撞
│  ├─ Foreground              # 小幅视差，遮挡边界明确
│  └─ Motion                  # 章时钟驱动的鱼、气泡、灯
├─ PersistentEffects           # 需跨房继续的短效/弹体，按稳定ID拥有
└─ AudioZones                  # 区域混合，不按切房事件重播
```

现有`physical_passages.gd`的26个地形实例继续提供碰撞。逐边将其旧`PaintedFloor`/`ledge`及背景图引用替换为对应分层资产；不要在外面再加一层可见地面导致双路。`connected_world.gd`继续负责空间和上下文，不把完整原画塞入该脚本。

原点变化的统一公式：

```text
world = local + activeOrigin
deltaOrigin = newOrigin - oldOrigin
newLocal = oldLocal - deltaOrigin
```

场景、相机position/follow_anchor、持久动件、效果和Shader里的`room_origin`/`scene_origin`一次更新。保存的世界锚点不随重新选房改变；界面仍用房间ID表示位置。不要在贴图fragment里把世界坐标直接除以本地room_size去采样局部蒙版。

### 当前实现的连续性缺项

| 当前行为 | 接入规则 | 状态 |
| --- | --- | --- |
| 同一角色与镜头沿连接行走，局部原点重定位 | 保留，新增样式不得重建角色或重置镜头 | 已有能力；新美术下待复验 |
| 一张共用远景等比放大覆盖整章 | 按世界锚点制作远景带和专用过渡片，保持真实尺度/地标 | 待制作 |
| 邻房初次激活时才建立敌人运行对象 | 提前准备可见邻区对象，按稳定ID去重；保留原激活/战斗规则 | 待实现/验证 |
| 自然跨房清掉`world_effects`和`clear_projectiles()` | 对仍存活对象迁入持久容器，保留相位/剩余寿命与世界位置；避免reparent触发caster退出销毁 | 待实现/验证 |
| 不同房间环境时钟及音频各自启停 | 接合段用章时钟，区域混音由距离驱动；共享素材不重复播放 | 待实现/验证 |
| 道路/平台贴图与独立前景裁片仍可见直边 | 重绘连接结构和两侧选区，逐件处理隐藏面、锚点与视差 | 待制作 |

## 六、视差、动态、光照与声音

### 视差

以章坐标定义每层原点和视差参考点，不以当前房间中心重新计算。贴住的骨架/根部/路面使用同一个变换；可玩层固定，不跟随玩家单独偏移。远景只有轻微相机响应，前景只在补齐的画幅余量内移动。

当前镜头默认1280×720，正常缩放约1、冲刺目标约1/1.05，前视85px。设计预览必须同时覆盖向左、向右、冲刺及画幅边缘，不从单张静帧推断不露边。

### 动态

使用一个可暂停章时钟和各动件固定相位偏移，禁止子件自己计时后又吃一次外部时钟。现有章`host.clock`或等效唯一源可作为方案；新接合段不强制重写全部历史动件，但进入接合带时不能重置新动件。

- 鱼：泳姿周期与移动路径独立，游到画幅边缘以前渐隐/转向，个体数有上限。
- 垂须/植物：同一根线固定，逐段弯曲，末端滞后；根部和骨架同速，不能出现贴着时不裂、相机一动就分离。
- 气泡：独立区域预热、大小/速度分层、边界渐隐与回收，暂停恢复不突发补发。
- 水域：只调节独立水面/背景光域，路面和角色不参与水波形变。
- 图中静态小装饰可以保留静止；未制成动画的挂须不得登记为动态已完成。

### 冷暖与声音

材质和色温的变化覆盖连接段中部，而不是一条竖线。灯光小幅平滑变化，保留贴图高光；光照调节不跨越整个世界来掩盖两张图色差。

同一水床循环可由章级单实例持续播放；不同腔室音色按空间权重淡入淡出。拟用权重`a=cos(t×π/2)`、`b=sin(t×π/2)`作为初始方案，`t`取玩家在混音带的位置并平滑；相关音频可能叠加变响，必须实际测峰值和试听后定增益。只声明混音方案，不把等功率公式当作听感已通过。

### 明确验收目标

以下数值为本项目拟定目标，当前尚未验证新样式：

1. **固定镜头**：每条主路左/中/右检查；无矩形边、双地面、明显重复块或材质/光向断裂。关闭前景和雾仍成立。
2. **脚底**：主接合段可见站立顶面与原碰撞目标偏差≤2px；碰撞与门槛数据变更数为0。装饰露出形体不能伪装成不存在的落点。
3. **连续性**：同角色跨界，既有速度/控制不被清零。以同一地标投影比较重定位前后，目标屏幕误差≤1px；不是比较两次正常走动后的屏幕坐标。
4. **视野**：当前画幅、左右反向、冲刺缩放及计划支持的宽屏实测，无露边/洞/缝。扩边不足返修原画，不拉伸。
5. **循环**：至少跨两次该动件完整周期与一次有界回收，暂停/恢复、离开返回、独立重载分别检查；效果与声音要连续观察/试听，不能仅看截图。
6. **玩法兼容**：主路双向、两支路上行/下返、能力门前后、Boss战、营地、死亡和V6独立重载。原工程57项和连通38项是已有回归入口，须重跑受影响流程并新增跨界专项。
7. **性能**：同机、同画幅、同渲染器、无录屏读回，分别记录暖机中位/p95和跨界长帧；与本批改前样本比较。原RTX5060的57–58FPS不自动延续为新版本保证。
8. **证据**：同视角设计/实机对照、每件实际引用与数量、跨界输入轨迹、录像/声音结果、资源哈希、未完成项。技术通过与用户美术评价分别记录。

## 八、执行入口与恢复

首个样板固定E01，不需要先改全部七房。机器合同含六边锚点、建议画布、原平台清单和来源哈希。运行`node tools/build-transition-contract.mjs`重新从源生成；源房数据/布局变化时先核对合同，不沿用旧截图作为新证据。

保存到每批进度：原始图、可编辑母版、运行PNG/图集、元素表、原件与运行哈希、静态/动态/玩法/构建各自状态、返修记录及下一具体动作。暂停后从未通过项接续，合格资源不重复生成。

本轮不修改正式场景、不导出新游戏，也不把提出的持久效果/预激活对象方案写成已成功配方。上一轮三个未提交Shader实验与候选平台仍保留，待E01定稿后再决定是否采用或替换。
