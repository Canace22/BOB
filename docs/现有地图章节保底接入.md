# 现有正式地图十二章保底接入

本文件描述 **现有19房地图上的剧情保底版本**，不是正在开发的新地图。地形、碰撞、母版及门的拓扑继续使用当前正式房间；十二章的 Boss、NPC 和事件按真实脚线重新摆放。本文的对白依据是已确认的白盒修订，不从旧剧情初稿恢复已删除台词。

主数据：[campaign_story.json](../game/content/narrative/campaign_story.json)。确定性离线生成入口：[build_existing_campaign_story.py](../game/tools/build_existing_campaign_story.py)。源文字、依赖和战斗结果仍由前三章对白/流程及第4–12章 JSON 拥有；正式入口只重新绑定位置与表现，不把白盒平台搬进遗城。

## 数据职责

每章保留 `id`、`chapter_id`、`next`、当前主要房间与正式 `transition_route`。每个阶段保留源稳定 ID 和 `kind`，单独填写 `room_id`、`at`、`support`、`checkpoint`。第4–12章保留源文件与 SHA，`source_at` 和 `source_objective` 只供差异复核，不能用于运行定位。

- `lines`、`captions` 保留已确认人物正文。前三章去掉“白盒验证结束”操作说明；正式目标去掉调试词。第一章只修改与单只护食甲冲突的数量及代词。
- `tasks` 保留稳定 ID、`requires`、`grant`；`required` 与 `any` 同时存在时仍为 AND，不能把任选观察改成必战条件。
- 每项 task 可以处在不同房间，第十一章三个触点即如此。指引不能只使用父 stage 的房间，距离检查也必须比较目标 task 的房间。
- `reward_abilities` 与叙事 `grant` 分开。旧门的 `boss`/能力判断由正式剧情桥接，不能再生旧母蟹、旧血巢等重复关卡 Boss 来领重复奖励。
- `actors` 使用 `ChapterCharacterActor` 已支持的稳定身份，位置为本房坐标。静态演员没有交战权；一旦同身份战斗或战后身体存在，演员应让位。封梁卫死后不能在下一段重建待机本人。
- 观察阶段可有 `captions`、定点居民和 `props`；时间压缩不表示已经制作救援、搬巢或水灾的正式逐帧人物动画，不能用静态平移冒充该项美术交付。

### 原有通行能力的保底衔接

现有正式地图有高跳、裂隙与组合门，故事路线若只换 Boss 而漏掉能力会卡死。数据按剧情完成事件授予：第一章离开聚食区后冲刺、须筛路线标记后浮游；第二章疏散后潜隙；第三章补巢后潮压；第六章返程后明确锚定；第九章清路与核对后骨音；第十一章收好计划后静默。运行方仍需以真实角色移动验证，而不是只检查能力布尔值。

### 危险交互与结算

第三章查看旧瓣与开瓣分属两个阶段。开瓣、脂库留缝、主闸移动窄封护带 `requires_fresh_press`，完成前一段的同一次 F 不得透传执行下一动作。关闭对白、换阶段或加载检查点时都要释放上一轮交互意图，保持“先看清、再主动操作”。

非致死结果：第二章守卫 `surrender`、第三章大甲 `retreat`、第七章实际撤离后止战、第九章两只甲分别 `retreat`、终章老守护者 `surrender`。第五章鳗与第八章封梁卫为 `kill`。不得为了统一完成接口把它们全改成击杀。

## 锚点与战场检查

所有 `support` 均记录本房原 `surfaces` 索引和 X，`at.y` 由原支撑线段插值得到；没有新增地板或覆盖现有碰撞。支撑线数据只是配置依据，实际 TSCN 可能被手动移动，因此必须在启用实际房间后做物理射线与真实键盘路径检查，尤其是已知的 R1-02 Surface1 偏移。

战场 `enemy.arena=[left,top,width,height]` 和 `floor_y` 用正式房内坐标，AI、弹体、潜地、回挂、水遁与撑跃必须共用该空间，不能继续夹取到试验场的 70..1210/520。主要战台净宽：R1-01 护食甲 650、R1-04 守卫 1220、R3-01 大甲 800、R4-01 执卫 1350、R4-03 封梁卫 1020、R5-08 老守护者 1180。R2-03 右平台鳗战目前仅 620，属于重点实机风险项；若潜地/吐卵受限，应复用本房下方已有宽地面，不能临时造隐形支撑。

恢复期是完整主线结尾；胜利弹体、卵和幻影清理后才能打开对白。跨房、死亡、退出和读档只允许一个敌人及战场容器拥有生命周期。检查点不保存半句游标，已经完成的危险行为、死亡与撤离事实不能因读档回滚成事故前。

## 本批数据验证与边界

离线已验证：12章、85阶段、54任务 ID 唯一；第4–12章全部源 stage ID 顺序、人物正文、观察字幕、任务标签、依赖、奖励事实、战斗 profile/结果保持；51条后九章任务合同逐项比对。源文件 SHA 全部记录，可检测后续源文案漂移。生成器语法检查通过，输出 JSON 可解析。

运行能力、界面头像、Boss实际技能覆盖、全线真实输入、独立存档恢复和碰撞接地由正式接入主任务统一验收，结果记录在 `game/progress.md`；不能用本离线数据比对替代。本文不接管新地图、不生成新地图资产，也不宣称新地图已经完成。


## 正式入口与运行职责

默认 `game/project.godot` 仍进入 `content/whalebelly/main.tscn`。`CampaignStory` 读取本表，只在正式游玩启用；历史QA、参考图捕获与临时练习保持隔离。旧房间的Boss/敌人生成在故事模式让位给本章完整执行器，不修改原房间JSON或碰撞。邻房仍由既有流式系统准备，只有活动房能触发剧情与开战。

故事进度由一个控制器拥有，阶段ID、任务事实和战斗结果存入正式V6的可选 `chapter_story` 字段；旧 `checkpoint/abilities/visited/narrative` 保留。白盒存档从不导入正式档。没有该字段的旧存档保留原能力、物品与位置，从第一章剧情开始补接，目标箭头会提示真实返程，不静默传送回起点。已完成的阶段按连续前缀恢复；未完成对话可重新触发，跳过对白不会代按下一个开瓣/留缝动作。阶段完成记录当前安全位置作为检查点；观察、战斗和对话的瞬态游标不保存。

当前交互使用 F。首次关键对白以正常步行/跳跃经过范围登记，在安全落地后播放；对话仍由既有 `WhaleCampaignDialogue/WhaleCampaignUI` 拥有暂停与按键释放。一次交互只完成一个任务，持住F不能穿透到下一次危险操作。三方向听骨任务各自读取真实room_id，不要求在首房完成其他房的触点。

任务HUD使用本章目标，出房时通过实际房门图搜索中继路线；原有各方向出口箭头保留，当前房内任务也有边缘指引与小型位图标记。剧情模式中的门条件由章节事实接管旧Boss解锁条件，仍保留邻房加载失败/未准备的提示；没有用新的隐形墙围住Boss场。

完整敌人空间、弹体与退场职责见[正式遭遇适配](formal-story-encounters.md)，头像及小窗口布局见[对话头像](dialogue-portraits.md)。静态NPC复用已有位图，救援/安置切到明确工作位；没有把静图平移称为逐帧演出。所有死亡/非致死身体只保留一份，撤退者失去伤害后退出画面。终章救援后老守护者保持投降存活，重进房间不会重新开战；结尾居民继续留在主闸。

## 本轮验证的证据边界

`tests/story/anchors_qa.gd`激活真实房间后检查222个脚线点（含跨房听骨任务）；这只证明支撑，不证明能走到。`tests/story/routes_qa.gd`从分腿起点开始，以实际Input动作走过29条前进/返程段和流式连接，含R1-02当前偏移低台二段跳、R1-05低顶短跳冲刺、胃枢四连锚环与主闸竖井。每腿起点/能力为明确夹具，腿内不定位；不是一次新档连续跑完全线。

`tests/story/flow_qa.gd`以显式房间/任务点定位、真实F对白/交互推进85阶段到结尾，战斗使用伤害夹具，不能作为战斗操作或徒步难度证据。另用 `combat_input_qa.gd`在每场正式战区以真实键盘事件通过全部9个必需战斗/撤离阶段，不改生命/敌人血量/无敌或直接结算；每场初始历史前缀是夹具。`reload_qa.gd`在第二个进程读取流程QA存档，检查85完成、结束标记及老守护者投降身体。正式场景截图与原生小窗头像截图分开；最终统计、限制和历史失败见game/progress.md。

复跑数据生成器会重新绑定来源正文与房内锚点；需要调整正式绑定时修改生成器再生成，不手改派生JSON。新增地形/新地图开发仍在另一会话，不属于此保底接入。

关键观察节点现已接入[场景内过场](formal-cinematics.md)，包括开场、第二章接应、第三章开瓣事故、第八章战后和终章救援/排水；独立F和原对白提交规则保持，取消/跳过边界与验证范围以该说明为准。
