# 资源存储与清理

## 入库边界

- 保留游戏实际加载的素材、正式 PNG/WebP 图集与 JSON、原画参考、可编辑源文件、提示词、来源和授权、资源台账、制作配方及人工验收结论。源文件与运行导出职责不同，不能仅因同名或体积大就删除。
- 管理页也是资源使用方。V5.2 的 `coverage.json` / `previews.json` 当前选用 11 张拼装图；它们及组件配方继续入库，忽略规则显式放行。新批次增加正式预览时同步维护清单与放行规则。
- 构建/代码 ZIP 快照、重复图集 ZIP、临时循环预览、诊断截图、自动验收报告、被拒稿和编辑器/构建缓存只保留本地。不要对整个资源目录执行 `git add -f`。唯一的原始下载包若没有可恢复的源文件，先核实后另行处理；不使用全局 `*.zip` 忽略规则。
- 已跟踪的文件不会因新增忽略规则自动退出 Git。先用 `git ls-files -ci --exclude-standard` 查遗漏，再核对清单、来源、人工结论和制作脚本输入，使用 `git rm --cached -- <明确文件>` 取消跟踪，保留本地文件。

## 图集复跑

分页图集 PNG/JSON 保留。ZIP 是它们的派生打包，新 checkout 不自带 ZIP。需要下载包或完整图集验证时，在仓库根目录依次执行（Python 需安装 Pillow）：

```powershell
python assets/source/whalefall-v5-2-complete/tools/pack-atlases.py
python assets/source/whalefall-v5-2-complete/tools/verify-atlases.py
```

打包读取当前台账；只有源素材与验收范围匹配时才能复现对应批次，不把历史报告视为当前通过。完整交付检查读取本地图集报告，须在图集验证后运行。制作配方和验证入口见[静态库操作与验证](../.agents/skills/bob-art-integration/references/static-library.md)。

## 历史与本地缓存

删除提交不会让旧历史自动变小。`git gc` 仅整理对象，不改写提交；本地历史 LFS 缓存用 `git lfs prune --verify-remote` 清理，先验证远端副本，失败时保留对象。所需旧资源可通过 `git lfs pull` 或按具体历史提交下载恢复。不要手删 `.git/objects` 或 `.git/lfs/objects`。

本次不改写历史、不删除备份分支、不强推；远端历史体积仍在。若后续需要缩减完整 clone 的历史下载体积，须另做历史重写及协作者迁移方案。
