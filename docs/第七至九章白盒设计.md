## 第七章：泵庭里的旧办法

拾潮者带来的记录不能证明试流已经能养活全部居民。老守护者也知道旧供养正在衰退，仍要靠修补泵膜争取安置时间。争论围绕能接多少住巢、薄弱支膜能否承受强流展开，鲸歌不承担说服功能。

| 阶段ID | 玩家操作与结果 |
| --- | --- |
| `ch07_evidence` | 分别到壳样台、采集记录按F；既说明新生长，也看到全城下降的刻线。两项都要核对。 |
| `ch07_dispute` | 到老守护者修补的位置交谈。先呈现他主动提供的灾变经历，再宣布停试流、停迁和收回调查通路资格。 |
| `ch07_make_copy` | 到拓片台按F制作副本。原件仍由主角携带，执卫要求全部留下。 |
| `ch07_blocked` | 主角说明要回迁居地，执卫横柄阻止携原件离开，才升级交战。 |
| `ch07_leave_pump` | 使用 `profile:5` 的完整水系执卫。开战后至少3秒，并实际退到窄道目标才算脱离；不要求击杀、击倒或打输。 |
| `ch07_called_off` | 脱离后立即停止敌对，再接老守护者喝止。主角带原件走，拓片留在台上。 |
| `ch07_exit` | 沿左侧维护道去骨穹腔，接应即将被停下的迁居。 |

撤离触发点为 `[2070,520]`，执卫位置 `[2310,520]`，窄道目标 `[1660,520]`。目标离触发点410，位于执卫左侧650，开战时不会已经站在完成区。全章保持连续地面；窄道、膜边和居民均为位置代理，不增设假空气墙或膜边伤害机关。水势与执卫技能仍由现有完整敌人负责。

这里撤回的是此前监督调查的通路资格，不将第二章“住户撤完后重开折井”改写成凭口头许可开门。独立启动的摘要明确了这个边界，运行依赖不引用第二章存档。

## 第八章：骨梁下的名字

封梁卫担忧新支撑承受不住强流。玩家先检查巢基和引水标记，说明有些地方可以接应、有些仍应等待。对方看过证据，仍执行停迁命令。补巢者提出已经失去旧菌床的具体困难，未能换来继续通行。

| 阶段ID | 玩家操作与结果 |
| --- | --- |
| `ch08_arrival` | 询问滞留的两户住巢，确认停迁和收索。 |
| `ch08_check_support` | 分别到固定巢基、引水标记按F，与封梁卫一起核对可安置和危险位置。 |
| `ch08_refusal` | 补巢者请求先接两户；封梁卫拒绝继续交流并清路，拾潮者站上骨梁。 |
| `ch08_beam_fight` | 使用 `profile:6`、`ending:kill` 的完整封梁卫。当前阶段只能在该战斗完成后继续，走到出口不能越过。 |
| `ch08_no_reply` | 到倒下位置按F确认。共鸣没有回应，负壳守卫赶来取下刻名薄壳，主角退开等待。 |
| `ch08_receive_nests` | 放回通行索 → 接回两户 → 照薄壳记录姓名。薄壳继续由负壳守卫保管。 |
| `ch08_exit` | 前往回流长腔，接应下一批迁居。 |

战斗触发点 `[1780,520]` 位于敌人 `[2140,520]` 前360。骨梁宽处支持换位，战斗完成前没有领取奖励或继续下一章的阶段。无回应的观察段可按F跳到同一终态；跳过时间不会跳过死亡事实、取名壳或后续搬巢。

战后不写庆祝、掉落或技法解锁。负壳守卫继续帮忙固定索，却不恢复与主角的交流。接巢任务以有向依赖约束顺序，不能先接巢再放回索。姓名记录不编造尚未定稿的个人姓名，表现为照刻痕抄录。

## 第九章：回来的水

回流长腔同时承担迁居接应和路线核对。清路发生在刻图调查之后、集中接巢之前。战后既有稳定的小菌床，也有支流太急、幼体无法附着的新巢，两种结果都必须检查。

| 阶段ID | 玩家操作与结果 |
| --- | --- |
| `ch09_find_routes` | 将行记对上头向、尾向道路，再询问避流台上的搬运居民。 |
| `ch09_clear_outer` | 在空台使用 `profile:0` 食腐甲完整行为，先以实际交锋逼退外围个体。 |
| `ch09_clear_rope` | 继续向右处理压索大个体，仍复用 `profile:0` 完整行为，以实际交锋逼退后才开放战后接巢任务。 |
| `ch09_check_outcomes` | 核对稳定菌床与失败新巢；在失败检查后重新封小口，再搬到内侧临时安置。四项全要完成。 |
| `ch09_record_old_loss` | 回到补巢者新居，在磨尽刻痕的旧壳旁补记胃室开瓣与菌床损失。 |
| `ch09_compare_return` | 把新丝、变薄旧壳、下降的供养刻线放在一起核对，确认尾根外排折回内圈。 |
| `ch09_receive_name_shell` | 负壳守卫带来修好的索扣，交付刻名薄壳，请主角亲口向老守护者说明梁上发生的事。 |
| `ch09_exit` | 携薄壳沿头向维护道去颅腔，核对封城记录后再准备尾根对峙。 |

清路按“外围 → 压索大个体”安排两场必经短遭遇，各自实际按键战胜后收束，不要求多个敌人同时扑击。外围战触发点为 `[1120,520]`、敌人位置 `[1400,520]`；压索战触发点为 `[1550,520]`、敌人位置 `[1780,520]`。两场都使用食腐甲完整行为和 `retreat` 结局，压索个体仅用实例参数设为生命8、高度90、半径30、显示名“压索食腐甲”，不改共用目录档案。两场完成后不再出怪，也不追加 Boss。失败水口的封回、住巢移位由位置交互与事实标记代理，没有连接正式19房水流模拟，也没有实际搬运实体。

补巢者没有因为主角补记损失而立刻原谅他。负壳守卫交付薄壳的目的，是让主角承担告知死亡的责任。收到薄壳之后先去头向记录，保持第十章放壳、对照撤离刻线、再收回的承接。

## 依赖、恢复与验证

第七、八章各有7阶段；第九章为完整保留两步清路增至8阶段，按合同顺序推进，`next` 分别为8、9、10。任务、阶段、事实均使用 `ch07_`、`ch08_`、`ch09_` 前缀。所有任务前置来自同章已存在且可先完成的任务，没有跨章隐形条件。退出是最后阶段，早到出口不会结束必经战斗。所有目标和检查点在连续地面上，原地R恢复和阶段持久化由统一运行器落实。

内容自查覆盖：JSON解析、字段种类、阶段/任务ID唯一、任务依赖是否存在、依赖无环、必需任务可达、坐标范围、敌人档案与结局、第七章撤离距离。自查结果由本批内容 Agent 汇报，完整 Godot 和实际按键证据由主 Agent 写入工程进度。

以下实机 case 留给主 Agent 统一执行：

1、在第七章开始撤离前走到窄道，不能提前结束；交战后退到目标完成，执卫和水系弹体即时停止，随后能看到喝止和原件去向。

2、第八章交战前绕到右端出口，不能越过战斗。击败封梁卫后，依次保留无回应、负壳守卫取名壳和三项接巢任务，没有奖励祝贺。

3、第八章尝试先接巢或先记录姓名，提示前置；放索后能接巢、记名并退出。死亡或R恢复不重演已经完成的战后阶段。

4、第九章必须先实际逼退外围食腐甲，再实际逼退压索大个体；仅完成第一场不能接巢。战后不再出怪，只检查成功菌床不能结束接应；检查失败新巢、封回小口、移巢之后才能继续。补记旧损失后能完成折返核对和接名壳。

5、连续完成第七至九章并独立启动各章，摘要与已定事件一致；第九章向第十章携薄壳与头向路线承接，中文均可显示，正式存档不受影响。
