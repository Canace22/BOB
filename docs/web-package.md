## 维护与检查

`game/tools/audit_resources.mjs` 默认检查整个可编辑工作区；加 `--release` 只从正式入口、项目配置和字体许可出发，展开七房、动作清单、UI、鱼群及音效的动态路径。两种清单不互相替代，发布范围外不表示源文件可以删除。

`tools/prepare-web-export.mjs` 根据正式依赖生成 `game/export_presets.cfg` 的 `resources` 选择及明确的JSON/TXT清单。它会验证共享控制器中每个旧动作均有完整当前图集，才能从发布排除其旧帧。增加动态路径或控制器动作时应维护引用规则；缺失图集必须先补齐，不能让过滤器隐藏失败。

Godot支持按选定资源及其依赖导出；JSON等非资源文件需要显式包含，见[官方导出说明](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html)。本项目仍以实际PCK和独立运行结果核实动态加载是否齐全。

导出后 `tools/audit-web-package.mjs` 读取实际PCK v4，检查每项MD5、导入/场景重映射、正式依赖完整性，以及测试/预览、旧帧、旧跑步图集和重复大载荷。Godot升级或PCK格式变化时先更新读取器，不跳过检查。报告只留在 `game/build/qa/package-audit/`。

最后，外部 `game/tests/whalebelly/exported_package.gd` 从空目录以 `--main-pack` 直接启动PCK；它不在包中，正式素材无法从编辑目录补漏。它检查36项动作、44张身体/FX图集、七房和共享待机底图，再调用已有音频清理流程退出。
