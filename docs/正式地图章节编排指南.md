## 二、先做事实图、空间图、锚点表

1、**章节事实图**：谁遇到什么、谁知道什么、玩家完成什么才放行。对白、交锋、危险操作和后果分别表达。

2、**空间路线图**：腔室、战区、安全台、可选支路、连接口、返程和可回望位置。一个章节可以含多个屏幕/加载房，一个房间也可以用于回访。**12章、加载房数量和旧19房索引不是同一个概念。**

3、**锚点绑定表**：交谈位置、敌人出生与活动区、机关、救援、拾取/固定点和出口各有稳定ID，再根据实际地形摆坐标。不要先堆素材，再靠任务文字解释一条不存在的路。

叙事路线为：须庭→折井→胃室→脂库→环居腔→肺缘→泵庭→骨穹腔→回流长腔→旧歌腔→回声室→经已走过的脊椎维护路返向尾根主闸。

这描述先后，不表示所有出口都在右边。第七章必须有真实可退的窄道，第十一章要返回维护网络再去尾根。应以环路或可识别快捷连接实现，不能无说明地从听骨传送到尾部。

当前R1须门、R2肺心、R3胃肠、R4脊椎、R5耳海只作为旧地图/素材盘点线索。不要把19房改名凑成12章；R3-01旧名“胃枢”不自动等于完整蓄养腔，R1-04旧母蟹也不等于负壳守卫。缺少脂库、骨梁、主闸职责时，应明确新增空间、连接与素材需求，不把概念图存在当作素材已经接入。

## 三、十二章的空间职责

| 章 | 必须具备的空间关系 | 玩家行动与下一步 |
| --- | --- | --- |
| 1 须庭 | 安全观察位→单体威胁→可分隔群战区→压轴窄口→可见下层口 | 通过读招/格挡/撤招解决核心威胁，再由居民指出折井；不能只跑过终点 |
| 2 折井 | 上沿/下降路→守卫封锁台→住巢断口/安全观察台→胃室口 | 先询问、再警告和非致死交锋；先停止敌对再救援，居民撤完才重开通路 |
| 3 胃室 | 菌床→浅槽→废弃低坑→旧瓣→真实返程台阶→旧壳/修补点 | 赶甲、查看、独立开瓣、事故、实际返回安置；修好巢片但菌床损失保留 |
| 4 脂库 | 采集刻线/低位观察/可选危险上层→水线住巢→限流闩/壳样架 | 必需拓印且任选一种观察，先移巢再试流，观察后收回部分开口 |
| 5 环居腔 | 幼体巢基/避流区与鳗战空槽分开→搬运接力位/留居系点 | 鳗必战死亡，之后搬整段巢基；有人迁走，也有人留下 |
| 6 肺缘 | 遮蔽观察与暴露台二选一→三处采样→脆膜/缓引水标记 | 可以不战取证；要有可引水的位置，也要保留不能开的薄弱处 |
| 7 泵庭 | 证据/修补/拓片台→长柄阻路→真实窄道→肋间维护路 | 争论后携原件撤离，实际到窄道即停战；不要求击倒或故意输给执卫 |
| 8 骨穹 | 滞留住巢/说明位→收索口/可换位骨梁→尸体/名壳→接巢台 | 必须交锋；封梁卫死亡后无回应、取名壳、放索接巢，不刷怪庆祝 |
| 9 回流长腔 | 刻图/避流台→外围空台→压索窄路→成功与失败案例→旧损失/名壳交接 | 两步清路后核对有成有败，封回不合适的小口，再去头向档案 |
| 10 旧歌腔 | 封城记忆片→薄壳槽→未刻写骨面→名录→耳侧维护口 | 放下薄壳、听鲸回声、补记姓名、收回薄壳；无必战或记忆Boss |
| 11 回声室 | 三方向听骨触点/记录台→分流图→回应处→返程出口 | 比较节律与回压，圈住未安顿区域，标有限外排；鲸歌不直接给答案 |
| 12 主闸 | 名壳/证据台→可见封护/决战区→稳台/窄封护/旧锚→恢复期结果 | 完整非致死决战后救人、共同稳闸、有限外排；结局不循环敌对 |

## 四、正式配置需要填写的绑定表

下表是交接要求，具体字段/节点由重构工作决定；本文件没有创建运行配置或加载器。

| 信息 | 要回答的问题 |
| --- | --- |
| chapter / source stage / task ID | 来源哪章、哪段事件？判断必须用稳定ID，不用显示名 |
| room_id / anchor_id / room-local position | 哪间房拥有？角色在哪个真实落脚面上？ |
| trigger volume / mode / fallback | 自动还是F？跳过中心、不同高度进入或回头时如何补接？ |
| requires / grant / result | 需要什么事实？哪次实际操作才产生结果并放行？ |
| actor / enemy / arena / outcome | 谁在场、能伤到谁、边界在哪里、死亡/退离/投降哪一种？ |
| checkpoint / interruption result | 死亡、R、退出或跳过之后恢复到哪里，保留什么？ |
| route / objective / cue | 可走地形、目标文字、箭头指向是否一致？ |
| art / collision / occlusion / QA | 素材实际加载了吗？脚线和遮挡是否匹配？哪条按键路线验收？ |

以第三章为例，必须分开这些锚点和行为：

| 来源阶段 | 正式锚点职责 | 触发及条件 |
| --- | --- | --- |
| `meet` | 补巢者与菌床旁的安全位 | 首次靠近自动交流，后续F重读 |
| `evidence/search → shell_warning → combat` | 大甲污槽接近区 | 进入就预警交锋，不以完成`basin`观察为前置 |
| `valve` | 旧瓣检查站位 | F查看；战斗结束只清危险，不代替开瓣 |
| `ready` | 明确的撬瓣操作位 | 松键后另一次F，才产生`valve_opened` |
| `rescue → aftermath` | 可见事故区和返回高台 | 先排水改善，再回水损毁；实际返回后再接救援交流 |
| `salvage → carry` | 旧壳和受损住巢各自的当地位置 | 先有物品再固定，不能隔空完成 |
| `repaired → complete` | 真正通往脂库的口 | 修补后放行，菌床损失不被重置成未发生 |

白盒x值、横向长度、F7/F8调试切章和矩形战场栏杆不是正式图规范。`at=[...,480]`也不一定是脚底高度，白盒地面常在520且有交互容差。正式房间按真实地形重放锚点，不复制坐标。

## 五、触发、对白与指引

- 首次关键交流的区域覆盖正常步行/跳跃路线；不能必须站进一盏小灯的中心。
- 高速越过后，在下一个安全落地位按稳定事实补接；不按对白里的某个词判断。
- 拒绝/警告先于交战；胜后先停攻击、弹体和追击，再接安全对白，不用强制暂停掩盖仍在运行的伤害。
- **可选观察不作敌人激活条件。**第三章已修过“没F看回水所以大甲不反应”，正式图不得重现。
- 危险动作独立交互，不能由打赢、对话结束或Esc跳过顺带执行。第三章开瓣、第四章留缝、第十二章移封护应明确可见。
- 目标写当前可做的事；位置用醒目颜色，边缘箭头按真实连接口与世界坐标定位。不能让玩家向右，却在空画面处用隐形墙拦住。
- F提示和真实范围重合，缺前置时说清先做什么，不显示一个无效按钮。
- 人物只回应自己知道的事。住户看到污絮回转，不等于已经知道整城故障；守卫不会因陌生人说听见鲸歌就接受强闯。不要用对白塞整页任务说明。

## 六、正式场景与敌人接入

### 地形和素材

正式数据由基础`game/art/whalebelly/rooms.json`、`game/content/whalebelly/layout/rooms.json`替换和`world/rooms.json`追加组成。七房母版在`layout/recipes.json`，后区有`world/recipes/`及对应生成器。先确定当前制作源与派生文件，不只改生成的TSCN/运行JSON，也不从`tests/fixtures`搬旧几何覆盖新图。

正式地形、支撑、背景、人物和道具要用真实2D位图；缺素材就登记补齐，不能把白盒方块换颜色当正式地图。绘画上可站的岸线要有碰撞，碰撞承托处也要看得见。敌人不能被营房中景遮到后面，前景不能遮住读招。

按当前角色跳跃包络验证平台，保留已认可手感。上下支路的下路必须真能通过，上路逐台可达；跳高和横跨不要同时取理论极限。薄台单向碰撞是白盒局部方案，不是全图统一替换要求。

### 完整敌人和空间参数

完整接入参考[ChapterRunEncounter.spawn](../game/src/prototypes/chapter_run/encounter.gd#L53)：鳗的潜地/吐卵、执卫水系、封梁卫格挡反击、老守护者复制/角色幻影都要保留。只加载同一张外观图不算接入。

特殊敌人包含试验场范围约定，如潜地/卵落点、捕食者挂点与遮蔽、水遁、撑杆腾跃等。白盒[整章坐标适配](../game/src/prototypes/chapter_run/catalog.gd#L14)是隔离样板的做法，**不是让正式遗城整体平移的方案**。正式接入应由负责方提供战场范围、脚线、挂点、撤离口等实际参数，并逐招核对身体、判定与弹体；不能只偏移父节点，让技能仍夹取到0..1280附近。

复用正式玩家/执行器，不为Boss另造第二个玩家控制器。每场遭遇唯一拥有AI与弹体；跨房冻结、邻房准备/卸载、胜后、死亡、重试、离场统一清理。未活动邻房不能提前攻击或推进剧情。

| 3 大甲 | `retreat` | 不自动设置`valve_opened` |

## 七、存档、回访和正式入口

白盒的`chapter-two-whitebox`、`chapter-three-whitebox`、`chapters-whitebox`是隔离测试进度，不能原样导入正式V6。正式接入由现有叙事/存档所有者或明确的新版本迁移管理，不同时运行两套主线状态机。

可以采用“完成stage＋局部task事实＋结局/结束位置”的职责，但给旧key加命名空间时须显式桥接，不能静默改名。当前房间检查点仍有索引语义：重排数量/顺序要用稳定room ID映射旧档，或定义新版本和回退入口，不把旧索引3解读成新数组第3房。双向连接、世界原点、邻房准备、地图节点和落点一并维护。

必须恢复以下组合：战前保留交流；胜后不复活敌人且尸体/伤者正确；事故中断回安全一致态；修补/搬迁中保留已完成任务；章末出口可走、回访不重复奖励或结局。不要出现物品已消失、任务却没保存的组合。

## 八、工作顺序和验收

1、先填事实图、空间图、锚点绑定表，圈出必战/可选战/危险动作/回访。

2、确认地形与素材来源，先做可达主路、返程和安全台，再绑事件；不能用目标文字补不存在的路。

3、接完整演员/敌人执行器，明确每个事件谁先结束、谁保存结果，避免双触发和两个进度所有者。

4、目标、箭头、交互范围、门条件与存档同批验收，不等玩家迷路后只改一句提示。

5、代码/场景/数据改动运行`node tools/godot.mjs check`和`node tools/godot.mjs test`，再实际按键走路线。区分新开局、夹具起点与连续通关；纯文档只核事实、链接和差异格式。

| 实际路线 | 必须证明 |
| --- | --- |
| 跳过可选观察，步行/跳跃越过入口 | 关键剧情能补接，怪物仍反应，不必回头找灯 |
| 不战4/6；再上台触怪后撤回 | 两路都可达，遮蔽/脱战真实有效 |
| 第7章不杀撤离，第8章尝试冲出口 | 前者抵达即止战，后者不能跳过核心交锋 |
| 第3章只看不撬，再撬开并退出/重进/修补 | 查看不改水路，结果独立保存，读档不卡任务 |
