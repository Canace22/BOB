# 场景与环境动态制作说明

整理日期：2026-10-31。以须门遗港 R1-01 当前工程为实例，说明从参考图到分层场景、独立动效，再到主关卡接入的制作方法。本次整理核对源码和已有证据，没有重新生成素材或运行游戏测试。

## 1. 整体方法

**参考图确定外观与构图，视频提供运动参考；先拆分、补齐遮挡区域并还原静态画面，再逐件制作动态，最后回到实际关卡检查。**

不是所有元素都需要相同制作工具：复杂柔性轮廓使用逐帧动画，轻微材质流动使用Shader，游动与回收使用路径逻辑。洞壁、道路等刚性结构保持稳定。正式画面由已制作的2D位图构成，脚本负责播放、摆放、视差和状态。

| 阶段 | 具体工作 | 必须留下的结果 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 参考分析 | 九宫格、边缘、前后遮挡、功能分类扫描；图像与运动参考分开 | 原件、元素ID清单、坐标与层级、运动简述 | 可见独立物件和装饰簇都有记录，未知项明确列出 |
| 分层资产 | 提取背景、地形、物件、动件；清除烘焙副本；补齐遮挡区域 | 独立RGBA、可编辑蒙版、干净背景、来源映射 | 根部、轮廓、透明边缘和镜头余量可用 |
| 静态重构 | 固定镜头，在Godot按原图摆放 | 同视角实机截图、差异记录 | 道路高度、主要轮廓、尺度、冷暖和遮挡对齐 |
| 动效制作 | 按元素选帧动画、Shader、路径或亮度动画 | 独立元素场景、动画母版、参数、预览 | 单件循环、边缘、附着点与运动范围通过 |
| 场景整合 | 统一时钟、层级、镜头偏移和暂停；接到主关卡 | 实际节点引用、全景及近景截图 | 无重复、接缝、露边或动态互相穿帮 |
| 运行交付 | 实际主场景检查、独立包启动、性能采样 | 截图/录像、检查结果、可编辑工程和进度 | 适用检查通过，限制与主观观感分别记录 |

## 2. 场景如何拆分

### 分层与当前实例

四个空间层是美术组织方式；实际绘制次序以节点 `z_index` 为准。一个空间层可包含多个绘制层。

| 空间层 | 内容 | 当前Godot例子与深度 | 制作重点 |
| --- | --- | --- | --- |
| 远景 | 水域、远处岩柱、深处光照 | `ENV-UNDERPAINT` -70、`ENV-DEPTH` -60、`WATER-SURFACE` -55 | 降低对比；补齐被动件遮挡的区域；水面限定在原水域 |
| 中景 | 骨架、鱼群、远处垂帘、光束 | `BEAM-*` -54、`MID-*` -50、远柱 -31、鱼群 -25 | 与道路分离；遮挡和视差不要重复计算 |
| 可玩空间及附属装饰 | 道路、洞壁、洞口、灯、顶部垂须、植物 | V3垂须 -1、洞顶/侧壁 0、道路 10、洞口 12、灯 13 | 道路刚性不变；角色能看清；垂须根带放到洞顶后方 |
| 前景 | 左上框景、底部暗色模糊组织、右下近景 | `FRONT-01` 50、两个边角 51 | 独立RGBA与补底；相接片使用相同视差，避免裂缝 |

角色、机关与碰撞由已有玩法场景拥有。环境贴图中的道路不自动产生碰撞；纯装饰没有必要新增碰撞。主关卡移除环境的展示角色，只保留实际游戏角色。

### 每个元素要登记什么

至少记录：**ID、参考图区域、位置、尺寸、图层、来源贴图、透明范围、锚点、是否运动、运动类型、参数、运行节点、验收方法**。交互、碰撞、声音、恢复状态按实际需求填写；纯装饰可写不适用及理由。

例如 `BALEEN-LEFT`：顶部左侧、固定根带、独立透明帧、48帧/12FPS/4秒；由环境统一时钟驱动，暂停保持当前帧；无碰撞、交互和声音；检查根部不漂移、尖端跟随、洞顶遮挡和循环衔接。

当前布局来源：[元素清单](../assets/source/xumen-motion-elements/elements.json)、[布局JSON](../assets/source/xumen-motion-elements/master/scene-layout.json)、[可编辑SVG](../assets/source/xumen-motion-elements/master/editable-layout.svg)。**实际场景引用是当前运行事实**：历史清单统计口径不同，不沿用旧版的100/106个元素总数。当前共享场景文件有61个直接子节点，包含展示角色；主关卡运行时去掉展示角色，鱼和气泡另由子节点生成，不能把这些数字直接相加当作同一口径。

### 提取、补绘与去重

1. 原参考图和视频原件保持不变，先保存哈希与真实资源绑定快照。
2. 同一静态装饰可以按簇拆分；需要独立摆动、路径或视差的部分必须单独保存。
3. 使用可编辑SVG/绘画蒙版提取原像素。需要生成式补绘时，只使用必要的隐藏区域，并记录它是补绘结果。
4. 动件移开后，底层必须有连续背景。前景则预留有限镜头移动余量，不能只补固定视角看得到的面积。
5. 从所有承载同一区域的贴图中清除旧动态副本：洞顶、所谓ROOT、背景、补底都要检查。名称不能证明贴图只包含根部。
6. 明暗底查看透明细丝；孤立层查看气泡、角色与光斑是否残留。保留静态高光可以，但不要让背景几何跟随光效移动。

## 3. 当前各类动态怎么做

| 元素 | 素材制作 | Godot运行方式 | 当前规格与重点 |
| --- | --- | --- | --- |
| 顶部垂须 | 已有绘画→8个派生关键姿态→周期指导片→ComfyUI/Wan2.2低强度细化→透明循环帧→Krita母版 | `baleen_frames.gd`驱动Sprite2D图集 | 3处共用48帧、12FPS、4秒；0/13/29帧错相；等比缩放、旋转，右侧镜像 |
| 远景蓝色垂帘/岩柱 | 沿用旧版场景裁片与视频运动派生帧 | 同一帧播放脚本 | 36帧、12FPS、3秒；资源含岩柱，不替换成乳白垂须 |
| 植物与藤蔓 | 独立透明原画，固定生长点，保留透明余量 | `pinned_foliage.gdshader`局部UV弯曲 | 4植物+4藤蔓；根部权重为0、末端渐增，各自错相；示例植物2.6px/7秒 |
| 鱼群 | 单鱼原画→头部约束的身体/尾鳍变形→32相位烘焙 | 每鱼Sprite2D帧动画，加独立队形路径与转向表现 | 3种，28/14/20只，共62只；队形16秒；单鱼按成员cycles/phase取帧，不统一每秒32帧 |
| 气泡 | 复用独立气泡PNG，按区配置数量与尺寸 | `bubble_emitter.gd`预先创建精灵，上升、横摆、淡入淡出并回收 | 7区共56个；近处少量气泡提高绘制层；数量有上限 |
| 背景水面 | 顶部水面裁片+透明蒙版 | `water_surface.gdshader`小幅折射原贴图 | 位置350,0，范围740×150；10秒，2.4px；不向道路或角色叠加漂浮水纹 |
| 光束 | 不含任何场景物体的独立透明柔光原画 | `soft_underwater_light.gdshader`内部微流动、边缘渐隐、加法呼吸 | 3束，12秒，强度0.12/0.08/0.055；固定主光方向 |
| 洞口灯光 | 独立灯光位图，洞口本体静止 | 亮度正弦缓变、加法混合 | 8秒，强度0.26；变化连续，不高频闪烁 |
| 前景/背景视差 | 分离近景、干净补底、边缘余量 | 位图位置按统一相机偏移计算 | 底部和相接边角倍率-0.14；中景/鱼群0.045；远处补底0.14；固定深度蒙版不跟着补底漂移 |

本场景没有在此次整理中新增“尘埃粒子系统”或玩法机关动画；可见漂浮细节不能自动登记为已独立制作的动态元素。新需求应另立元素ID。

### A. 垂须：复杂柔性轮廓做成帧动画

![八个对齐关键姿态](../assets/source/baleen-loop-v3/review/eight-keyposes.jpg)

当前用的是 **绘画原件 + 周期运动指导 + Wan材质细化 + Krita可编辑帧**，工具职责如下：

- **绘画原件/关键姿态**：保留V2干净原画，派生8个对齐姿态。根部固定，中段先弯，下段跟随，尖端滞后且摆幅更大；小簇之间错开相位。派生变形不称为新手绘。
- **ComfyUI + Wan2.2 TI2V 5B**：实际执行低强度视频细化，保留工作流、种子、模型名、任务ID和原始输出。已用参数为20步、CFG 2.0、denoise 0.10；它是本资产的已用值，不是所有动画的通用最佳值。
- **循环与透明后期**：模型颜色变化先回到原画坐标，再限制为周期材质变化，以22%权重混合；透明轮廓与运动轨迹仍由指导原画控制。根部不加入模型变化。不能把最终帧称为模型视频直接抠帧。
- **Krita**：8层关键姿态KRA、48关键帧原生动画KRA；由真实Krita导出所有帧逐像素复查。现有方法包含ORA原生转换与时间轴组织，不是声称Krita手工画完全部中间帧。
- **Godot**：仅播放已经烘焙好的透明帧。共享3072×2304图集，8列×6行，每格384×384；实例独立设相位与附着变换。

本项目约定12FPS并按源视频实际时长向上取整：

`目标帧数 = ceil(实际解码帧数 ÷ 源FPS) × 12`

当前Wan输出73帧/24FPS，实际3.041667秒，因此48帧/4秒；将完整设计循环均匀放慢到4秒。2.3秒源片按同一规则是36帧/3秒。这是项目交付规则，需记录重定时方式，不是原速抽帧。

循环采样用 `phase = 2π × frame / 48`，最后不重复放一张首帧。要检查首尾的位置与速度衔接，也要比较接缝的像素变化和普通帧间变化。只检查首尾图相似不能证明运动自然。

当前指导轨迹测得下段峰峰值约17.5px、细尖约36.5px，细尖主频延迟约0.276秒；这些是设计轨迹测量，不是逐根真实纤维追踪。自然度仍需播放确认。

制作与复跑入口：[制作脚本](../tools/baleen_loop_v3.py)、[Krita转换脚本](../tools/baleen_kra_native.py)、[接入脚本](../tools/integrate_baleen_loop_v3.py)、[完整记录](../assets/source/baleen-loop-v3/integration/README.md)。历史Blender绘画网格烘焙与旧Wan光流投射方案保留在源目录，顶部三处当前不再使用这些旧图集。

### B. 鱼群：身体动作与游动路径分别制作

单鱼原画保留头部识别与体型，对身体、尾鳍做柔性变形，烘焙32张透明动作帧。每鱼再有位置偏移、尺寸、颜色深度、起始相位和周期次数。

三组路径分别是持续穿越、聚散回游和弧形队列。按路径速度方向调朝向与少量角度，转侧时压窄宽度表现转向；这是2D表现，不是完整3D转身。跨边界回收先淡出，不能在屏幕内突然跳回。摆尾与队形共享可暂停时钟，但分别核对循环。

原画和动作母版在[鱼群源目录](../assets/source/fish-schools-v01/README.md)；实际播放为 [fish_school_v01.gd](../godot/WhalebellyRuins/scenes/environment/elements/fish_school_v01.gd)。没有鱼群碰撞、受惊AI或伤害。

### C. 气泡：透明位图实例与区域回收

按岩缝、桥下空腔和开阔水域划区。每区配置 `bounds`、`population`、`size_range`、`base_speed`、`bubble_opacity`，个体预先分布到不同高度，避免开场一起从底部出现。

按时间计算上升位置和小幅横摆，在区间上下边界淡入淡出后回收同一批实例。近处气泡需要独立深度，不能仅把背景气泡放大。当前7区56实例，无需持续创建与销毁节点；实现是精灵池，不是GPUParticles2D。

参考：[发射器脚本](../godot/WhalebellyRuins/scenes/environment/elements/bubble_emitter.gd)、[桥下修复与三个新增区域](../assets/source/xumen-underbridge-repair/README.md)。

### D. 水面与光束：不同效果分开处理

**水面**只采样背景中的真实水域裁片，做局部折射；蒙版边界限制变化范围，位于骨架、洞顶与垂须后方。当前不使用旧CAUSTIC漂浮叠片；历史文件仍在目录不表示正在运行。

**光束**必须是一张独立透明光效图，不能拿含岩石、洞壁的场景裁片做加法移动。当前光束只在纹理内部轻微流动与呼吸，固定几何位置和光照方向。材质高光可以留在静态贴图，不要求全部实时打灯。

Shader手动采样贴图时，应核对`COLOR`是否已含贴图颜色与Alpha，避免重复乘法让效果变暗、变薄。分别检查关闭效果的底图、仅效果层和完整场景。

参考：[水面Shader](../godot/WhalebellyRuins/scenes/environment/elements/water_surface.gdshader)、[柔光制作与棱角修复](../assets/source/xumen-soft-light/README.md)。

### E. 植物、藤蔓与前景

植物/藤蔓使用透明原画与根部权重Shader：生长点不动，权重向末端增长；小幅摆动且节奏错开。不要把洞顶、道路或带岩壁的整片图一起扭曲。透明余量必须覆盖最大摆幅。

前景从洞壁和底图中拆出来后，还要清除所有底层副本。左上、底部、右下相接处使用同一倍率，保留32px有限余量与局部补底。前景跟随感来自它与世界层不同的相机响应，不是把前景绑在角色身上。

角色跟随由现有 [campaign_camera.gd](../godot/WhalebellyRuins/scripts/campaign_camera.gd) 计算，环境接收相机偏移；`Tab`切换跟随与全房视图。来源、蒙版及接缝修复见[前景说明](../assets/source/xumen-foreground-edges/README.md)。

## 4. 统一接入方式

环境子件集中在 `godot/WhalebellyRuins/scenes/environment/elements/`，总布局在 [xumen_reference.tscn](../godot/WhalebellyRuins/scenes/environment/xumen_reference.tscn)。

[`reference_environment.gd`](../godot/WhalebellyRuins/scenes/environment/reference_environment.gd)维护一个`elapsed`时钟，将时间和相机偏移传给各子件的`update_at()`。帧动画/植物/光束使用`external_clock=true`，鱼群使用`autoplay=false`；独立预览时可自行计时。避免环境与子件同时累加时间导致双倍速度。

关掉动画保持当前姿态；速度归零、场景树暂停也应冻结。恢复时从原姿态继续；重载则按相同初值和预热分布初始化。循环用统一时钟不意味着所有元素周期相同，不能要求4秒时整场景所有效果都回到首帧。

主关卡复用环境PackedScene，物理和玩法不跟着视觉拆分而重做。替换前保存受保护文件哈希与旧绑定；素材接入通过后再更新现有便携PCK。所有制作与开发留在唯一Godot工程，不另开版本工程。

| 类型 | 放置与用途 |
| --- | --- |
| 原件 | `assets/source/<批次>/original`或`source`：参考图、视频、生成原稿，不覆盖 |
| 母版 | 同批次`master`、`krita`、SVG、动作曲线脚本、Comfy工作流：支持继续编辑 |
| 运行资源 | `assets/runtime/`：PNG帧/图集；Godot `assets/`保存实际加载副本 |
| 场景与播放 | Godot `scenes/environment/`：独立元素、布局、Shader与播放脚本 |
| 来源和接续 | `manifest.json`、`provenance.json`、`progress.json`：规格、来源、状态、下个动作 |
| 证据 | 对应源批次`review/`和工程`evidence/`：实际截图、录像、测量与失败记录 |

Krita用于绘画修整与可编辑时间轴；ComfyUI负责调用Wan视频模型；Blender可用于绘画贴片/网格烘焙等特定分支；Godot负责真实组合和运行；Python/FFmpeg用于确定性处理、图集、视频与验证。只选择任务需要的工具，不能因清单里出现就宣称本机可用或本批已经使用。

尺寸、透明边缘和锚点应统一。静态图集、动作帧图集与源视频分开登记。模型输出、补间、变形烘焙和人工绘画注明真实方法，不将“生成完成”写成“场景验收完成”。

## 6. 验收与返修

1. **静态对照**：同画幅固定镜头，比较轮廓、道路高度、附着点、尺度、冷暖与遮挡；关闭动效再检查背景连续性。
2. **单件动态**：检查根部、末端、相位、回收与循环；明暗底查看细丝和Alpha；隔离动件验证刚性区域没有变化。
3. **镜头与状态**：全景、近景、左右边界、小幅纵移；暂停/恢复、动画开关、零速、重载以及换房返回。
4. **实际主关卡**：核对真实加载引用和唯一角色；用当前控制器移动/跳跃检查遮挡。显式换房测试不冒称完整通关。
5. **独立包与性能**：临时包实际启动通过后替换正式试玩包；录像与不录制性能采样分开，记录设备、渲染器、分位帧时间和贴图内存。

例如使用固定Godot4.7.2，在BOB根目录运行：

```text
Godot --path godot/WhalebellyRuins --audio-driver Dummy --script res://tests/baleen_loop_v3.gd -- --baleen-mode=environment
Godot --path godot/WhalebellyRuins --audio-driver Dummy --script res://tests/baleen_loop_v3.gd -- --baleen-mode=main
```

`Godot`代表本机固定版本的可执行文件，非保证已加入PATH。需要截图的检查不能用headless代替。Dummy音频仅适合不验收声音的检查。

历史脚本的旧36帧/72帧断言、旧控制器输入或旧ROOT分离假设可能与当前资源不符，复跑前先读断言并确认适用版本；失败不能未经分析就改成通过。不要直接执行整版生成器覆盖手工改图，先检查其重建范围和后置接入顺序。

### 已有证据与当前边界

上一批V3接入报告记录：23项垂须定向、14项主场景、17项环境回归、14项独立包检查通过；另有10秒不录制环境采样P50 16.673ms、P95 16.834ms。证据和适用范围在[原报告](../assets/source/baleen-loop-v3/integration/result.json)，**不是2026-10-31重新实测**。

已出现并修复的问题包括：静态ROOT残留细丝、前景分件裂缝、道路下缘被蒙版裁短、含岩石的光束产生棱角、透明Shader重复乘Alpha，以及把岩柱误认为纯垂须。每次都定位实际 owning layer 和资源，再局部修复，不用气泡/模糊掩盖缺口。

后续制作建议按“固定镜头代表样板→单件动态→小范围接入→实机与包体验证”推进。技术检查、代理截图复核、连续播放观感和用户美术确认分别保存；未观察的内容继续标为待验证。
