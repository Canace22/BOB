# BOB 美术资源接入

先确定目标是初版还是新版，读取[协作规则](../../../AGENTS.md)与该版 `renderer.js`、`levels.js` 的相关部分。图片制作按需复用 `consistent-2d-game-assets`、`imagegen`，模型制作按需复用 `meshy-blender-character`；本文件只记录 BOB 的现有接口与验收边界。

## 输入与产物

- 参考从[原画集入口](../../../docs/鲸腹遗城原画集/README.md)和用户指定素材查起。已有获认可的游戏截图优先用于保持运行画面一致；概念原画、V2 设计和已实现关卡分别核对。
- 原图、提示词、设计和清单沿用 `docs/鲸腹遗城原画集/` 对应版本目录。新增模型、贴图、动画与音频遵循[资源目录约定](../../../assets/README.md)，制作源放 `assets/source/`，游戏导出放 `assets/runtime/`；同步[资源台账](../../../assets/catalog.md)，记录实际输出、来源授权、运行引用及接入状态，不覆盖唯一原件。
- 证据放在受影响版本的 `output/<任务>/`，结论与复跑入口写入该版 `progress.md`。这些输出被 Git 忽略，不能假设新 checkout 自带截图。

## 接入步骤

1. 核对运行入口和设计范围。两版分别维护自己的关卡、存档和绘制，不因题材相同合并运行逻辑；外观替换保持原机关 ID、收集状态和出口条件。
2. 初版 `mvp/renderer.js` 加载四张原画：`00_鲸落全景.png`、`01_鲸口门庭.png`、`08_肋骨穹顶.png`、`05_心室潮泵.png`；`game.js` 的地图缩略图也有路径引用。源码使用 `../<文件名>`，原图实际存放在原画集，须检查 HTTP 请求解析到哪里，不能仅凭文件存在认定本地加载成功。发布脚本会复制这四张图到站点根目录；换图时同步核对加载映射、缩略图和发布清单。
3. 初版画布逻辑尺寸为 1280×720，碰撞由关卡数据和游戏逻辑负责。背景裁切有意避开原画中的人物；调整裁切后检查是否出现重复主角、挡住机关或让视觉地面偏离实际平台。图像失败时有程序绘制背景，须确认回退后仍可游玩。
4. 新版当前由 `mvp-nightmare/renderer.js` 生成几何场景。逻辑 x、y 转入场景时按 100 缩放，竖直映射为 `(574 - y) / 100`，z 直接作为场景纵深；角色位置使用逻辑包围盒的底边中心。模型接入先核对单位、轴向、原点和当前调用处，不照搬灰溪镇的尺寸或骨骼契约。正式模型加载、动作绑定和失败回退若为本次需求，需实际实现并验证后才能登记为已有能力。
5. 新版 Three.js 开发导入与发布导入不同，由 `mvp/deploy.mjs` 复制 vendor 文件并替换导入。新增资源需检查是否被打包：现有脚本不会自动递归收集任意素材目录。按实际需要补充复制规则，保留可恢复的原资源和引用。

## 验证与恢复

按[桌面回归验收](../bob-desktop-verification/SKILL.md)选择检查，至少覆盖本次相关的 3–5 项：

1. 实际桌面截图中的比例、接地、前后遮挡、背景裁切和机关辨识度；合成预览不能代替实机。
2. 真实键盘走过受影响的平台、交互点和出口；新版另检查纵深位置、蹲下藏身与镜头。
3. 替换前后机关、回声或记忆、死亡重试与刷新恢复保持可用。
4. 主动阻断本次资源请求并核对现有回退；缺少回退时明确记录实际失败表现，需要补齐时再实现。
5. 发布链路受影响时构建两版，检查带仓库名前缀的资源地址和运行画面。

失败时保留报告，恢复本次资源及对应映射，不回滚无关代码或清空浏览器全部存档。技术检查、实际视觉检查与用户美术接受分别记录。
