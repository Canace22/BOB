# BOB 美术资源接入

先确定任务是素材制作入库、资源管理还是游戏接入，读取[协作规则](../../../AGENTS.md)；明确 `mvp-v2/`（当前发布的 Canvas 2D）、`mvp-nightmare/`（Three.js 2.5D）或 `mvp/`（初版），再读取该版 `renderer.js`、`levels.js` 的相关部分，不凭“新版”名称判断技术版本。图片制作按需复用 `imagegen`；本文件只记录 BOB 的现有接口与验收边界。

## 输入与产物

先遵循根[正式2D美术规则](../../../AGENTS.md#正式美术必须使用2d素材)与[持续交付流程](../../../AGENTS.md#持续迭代与边做边玩)。缺少结构或特效图片时补绘入库；禁止用程序柱体、纯色多边形或非等比拉伸横图冒充正式外观。Canvas 只负责图片与状态的运行组合，缺图回退不算美术完成。

制作与替换先核对[美术风格规范](../../../assets/art-style.md)；它描述目标风格，不代表各版已完成统一验收。

- 参考从[原画集入口](../../../docs/鲸腹遗城原画集/README.md)和用户指定素材查起。已有获认可的游戏截图优先用于保持运行画面一致；概念原画、V2 设计和已实现关卡分别核对。
- 既有原画与设计资料保留在 `docs/鲸腹遗城原画集/` 对应版本目录。新增模型、贴图、动画与音频遵循[资源目录约定](../../../assets/README.md)，制作源及新提示词放 `assets/source/`，游戏导出放 `assets/runtime/`；在 `assets/catalog.json` 记录实际输出、来源授权、运行引用及接入状态，[批次索引](../../../assets/catalog.md)保留概念资料和批次入口，不覆盖唯一原件。
- 静态库证据放对应 `assets/source/<批次>/review/`，结论写该批次 `acceptance.md`；管理页验证写 `assets/manager/progress.md`。游戏接入证据放受影响版本的 `output/<任务>/`，结论与复跑入口写入该版 `progress.md`。截图等本机证据按实际 Git 状态记录，不能假设新 checkout 自带。

## 接入步骤

### 先入库、再接入

如果任务仅为整理和管理素材，使用 [assets 管理说明](../../../assets/README.md)中的本地管理服务与 `assets/catalog.json`。原始 PNG 不覆盖；参考、提示词链与验收证据放对应 `source/<ID>/` 或批次源目录。页面修改名称、标签、备注与验收状态会保存到 JSON；`catalog.md` 只维护概念资料和批次索引，避免重复维护可变状态。入库后仍保留 `integrationStatus: not-integrated`，直到实际修改游戏加载器并通过接入检查。

静态精灵、静态图集、动画帧序列分开标记。使用 `assets/source/whalefall-static-atlas/pack-atlas.mjs` 重新打包时，核对统一 px/U、frame 矩形、裁片后的 pivot、原始来源和边缘间隔；逐个裁片实际合成验证，不能因 atlas 有多个 frame 就把它作为行走或攻击动画。管理页面自身的保存/刷新、版本冲突与归档恢复使用 `assets/manager/` 的检查与测试，不需要因此改动游戏或运行发布。

全量入库、组合复跑、图集更新或管理页修改时，按需读取[静态库操作与验证](references/static-library.md)，其中列出真实脚本、输入输出与恢复方法。已有报告是历史证据；本轮只改文档时，验证格式、链接和事实即可。

### 完整设计制作

两份 V5.2 页面是同一设计的简版与详版，先读 `assets/source/whalefall-v5-2-complete/coverage.json` 与其 `inventory/`。需求家族、状态文件、图集 frame 和房间实例分别计数；房间映射是查漏依据，不代表已拼完可玩关卡。每个家族都要关联实际输出或明确的状态组合规则；完成清单后回查源设计中的形态变化、攻击物、投影与层次，避免跨类别漏项。数量按本次需求盘点确定，不能把一批样例或历史批次总数当全量完成。

完整静态打包用该目录 `tools/pack-atlases.py` 与 `tools/verify-atlases.py`，保留逐件 PNG；UI 保留整张原生画布与九宫格参数，世界精灵按 128 px/U；L0/L1 背景独立保存并保留全画布投影。母蟹等同体状态使用共同的像素比例和根位置，不因脱壳后包围盒变小而放大。页面列表使用缩略图，详情读取原图；缩略图不计新增资源、不覆盖源图。

### 游戏加载与运行

V5.2 主线入口使用 `campaign-levels.js / campaign-renderer.js`，旧四区 `levels.js / renderer.js` 保留在 `legacy.html`。两套复用运行清单与 WebP，但来源房间与机关语义分别验收。详见 [CAMPAIGN.md](../../../mvp-v2/CAMPAIGN.md)：源文字已给的坐标/连接与不可获取的 SVG 布局必须区分；未知地形标记 `adapted-from-source`，不能把美术房间参考图当已经复现的完整关卡。静态首领预告与攻击范围由引擎状态绘制，画面预告与真实伤害体积要一致；体宽包括肢端时，碰撞体可以略收窄，但需要实际截图对齐验证。R1 食管育窝不能继续绘成鲸须区背景。

源图的连续丘脊不能只改成矩形台阶或把坡面当背景。采用加密折线时，绘制、碰撞、小地图共用采样点；保留出生/敌人/出口锚点。运行贴图保持不规则下缘，避免把材质竖向拉伸到屏底；支撑必须有独立2D素材，不用横向平台裁片拉成长柱。新增侧台后复核跨台训练等依赖平台身份的条件，防止同一岸上的小侧台被当成跨过教学沟。屏幕前景必须在恢复世界相机变换之后绘制，否则纵向镜头会把底部装饰带到半空；多层平台和凹谷必须分别截图检查，不能仅凭通关通过判定美术合格。

1. 核对运行入口和设计范围。各版分别维护自己的关卡、存档和绘制，不因题材相同合并运行逻辑；外观替换保持原机关 ID、收集状态和出口条件。
2. V2 的 [art-manifest.js](../../../mvp-v2/art-manifest.js)选择当前玩法需要的来源 ID，由 [export-runtime-art.py](../../../mvp-v2/tools/export-runtime-art.py)从台账原图生成缩放 WebP 和运行元数据；导出命令与目录见[资源管理说明](../../../assets/README.md)。不要直接把制作分辨率的原图当游戏贴图发布；原件、台账 `file` 和原始来源保持不变，接入记录的 `runtimeFile` 指向派生文件。来源 R1 / R3 / R2 / R4 对应鲸口 / 胃库 / 肺缘 / 肋骨，其中肋骨借用骨架材质，不代表复现 R4 完整设计。新增引用先核对实际语义，不能为了用齐资源扩写未要求的关卡或机制。
3. V2 世界精灵按源尺度换算，默认 1 U = 48 逻辑像素；角色落脚点为碰撞盒底边中心，左右姿态分别取图。导出的 bbox / pivot 已转换到导出像素；代码中额外写出的源像素裁切、边距和挂点，横向乘 `exportScale`，纵向乘 `exportScaleY`，不能重复缩放已有 bbox / pivot。背景保留完整画布与透明留白，分层视差。矩形平台裁切贴齐碰撞高度；坡面由 `levels.js` 的 `terrain.points`、`terrain.js` 碰撞采样、`runtime-art.js` 缓存绘制和 `scene-lab.js` 多边形共同消费，不能只改贴图起伏。静态角色可伴随程序反馈，但不得登记成逐帧动画；缺图回退须主动阻断请求检验。
4. V2 开发服务只映射共享 `/assets/runtime/sprites/`；本地快照与 `mvp/deploy.mjs` 按运行清单复制选中的 WebP，保留 `../assets/runtime/sprites/...` 相对路径。检查 `/BOB/mvp-v2/` 与快照版本路径，不复制制作源或整个素材库。当前 Pages 仅发布 V2 与所需导出资源，旧入口仅重定向，不包含初版原画或 Three.js vendor。
5. 初版 `mvp/renderer.js` 引用四张概念原画，`game.js` 另有地图缩略图。原件位于原画集，源码路径与本地服务需实际核对；当前 V2 构建不为初版补齐资源。初版画布为 1280×720，调整裁切时检查重复主角、机关遮挡和平台对齐，另验证程序背景回退。
6. Three.js 版本 `mvp-nightmare/renderer.js` 仍生成几何场景。逻辑 x、y 按 100 缩放，竖直映射为 `(574 - y) / 100`，z 为纵深；角色位置使用逻辑包围盒底边中心。模型接入先核对单位、轴向和原点；正式模型加载、动作绑定、失败回退及单独发布流程若为本次需求，需实际实现并验证。

## 验证与恢复

按[桌面回归验收](../bob-desktop-verification/SKILL.md)选择检查，至少覆盖本次相关的 3–5 项：

1. 实际桌面截图中的比例、接地、前后遮挡、背景裁切和机关辨识度；合成预览不能代替实机。
2. 真实键盘走过受影响的平台、交互点和出口；V2 检查攀网、升降台、摆荡、浮膜和生态状态，Three.js 版另检查纵深位置、蹲下藏身与镜头。
3. 替换前后机关、回声或记忆、死亡重试与刷新恢复保持可用。改变地形高度时检查对象落脚、区域返回出生点与旧存档检查点；不能只验证新开局向前走，旧坐标可能落到坡下或悬空。
4. 主动阻断本次资源请求并核对现有回退；缺少回退时明确记录实际失败表现，需要补齐时再实现。
5. 发布链路受影响时运行当前 V2 Pages 构建并检查带仓库名前缀的资源地址和运行画面；按协作规则补做相关版本语法检查。远端发布后核对线上模块和资源确实更新，不把构建成功视为已上线。

“边做边玩”先确认用户正在玩的入口。公网 Pages 在验证完成后再部署，部署期间可继续玩旧页，刷新进入新版；本地稳定试玩使用不可变快照，保留旧版本资源并由玩家选择更新。用户已明确要求更新 Pages 时，沿用本轮发布授权，完成验证、部署和远端检查，不以本地快照代替，也不重复要求同一授权。

## Godot逐帧角色接入

唯一工程为 `godot/WhalebellyRuins`。V2.4专项导入见该工程 `tools/player_import.py` 与 `docs/tide-3c.md`：读取实际JSON和生产根锚点，不把HTML说明虚构成逐帧坐标。已去紫的源图不重复阈值清理；统一裁剪必须校验所有帧Alpha总量和RGBA裁剪像素。源图自带平移/跳跃展示轨迹时，应去除展示位移再交由物理控制，不按每帧外接框各自缩放。

完整展示库与游戏短片段分开；命中时刻使用Animation marker，标明新增战斗映射与原始图像阶段的区别。AnimationTree活动时不同时用AnimationPlayer.play控制相同轨道。字符串动作轨道需过滤空值，并在所有运行片段显式赋值，避免混合器默认回写空字符串导致资源路径缺动作ID。固定引擎导入完成后再生成引用资源；逻辑回归与实际GPU截帧都通过后再接入。原图缺少中间姿势不能用导入成功冒充动画已修好。

失败时保留报告，恢复本次资源及对应映射，不回滚无关代码或清空浏览器全部存档。技术检查、实际视觉检查与用户美术接受分别记录。

主场景迁移需先记录启动入口、活跃控制器数值、碰撞层、存档接口和受保护场景哈希，再用相同数值运行独立PlayerTest。CampaignPlayer继承基础场景，以适配层调用旧敌人/交互/机关；跨房间HUD必须断开旧角色信号并重绑。参数保存在派生场景，避免_ready覆盖Inspector。仅中心点落在真实表面内侧安全余量时更新last_safe，ground_y无命中时返回传入高度，不能单独作安全落点判断。普通短跳截断不能吞掉旧机关强弹跳。自动门需要出生保护，并排除与营地重叠的返回门。连续走图测试应使用实际攻击/跳跃/技能策略，既验收单房接口，也验收Boss解锁后到出口的路径；QA存档复跑必须串行。
