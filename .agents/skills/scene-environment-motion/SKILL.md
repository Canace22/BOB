# 场景与环境动态制作

目标是可编辑、实际运行、构图稳定且运动可信的场景。主动识别该动什么、为什么动、怎样制作；按运动结构迁移成功经验，不要求用户逐件指出。通用于新场景及已有场景迭代，项目题材、引擎、模型、FPS和预算从本次任务读取。

## 触发与范围

- 用户要求制作/还原/优化场景、环境表现、分层视差或单个环境动件时使用本流程。项目已要求默认使用时，即使未写Skill名也应用。
- 先识别交付边界：纯场景、独立动件、主关卡接入，或完整玩法关卡。复用既有项目；不因环境动效自动增加战斗、角色控制、碰撞、声音或画外地图。只制作Skill或方案时交付流程，不启动生产。
- 有现成制作总流程时，本Skill负责场景/环境表现分支，总流程继续负责原有玩法与构建；避免两套流程互相要求重复验收。保留用户指定工具、风格和已授权范围。

## 1. 读取现场并主动判读

1. 读取项目约定、实际运行入口、引擎版本、风格参考、资产来源、既有场景和进度。核对可调用工具，不能从候选工具表推断已安装。
2. 先实际查看参考图和场景截图；有视频则检查解码时长/FPS，取代表帧，并观察可信运动与时间戳。文本描述或资产名不能替代看图。
3. 按九宫格、画面四边、前中后层及遮挡关系扫描，建立元素ID。独立物件、重复实例规则、静态装饰簇分别计数，避免混用节点数、鱼只数、资产数。
4. 对每件给出 `static / motion / inspect` 判断、理由和优先级。考虑材质、根部、流体/风向、生命活动、尺度、景深及可读性。用observed、inferred、proposed区分观察、推断、设计；静态图不能证明周期和速度。
5. 对潜在动件主动填写“运动结构→首选方法→备选→取舍→样板检查”。使用[方法与配方库](references/motion-recipes.md)，不要按物件名字机械套模型。图中没有的元素不因配方库存在而自动添加。

先用一两句话向用户说明识别出的主要动件与选型，然后在授权内继续执行。可逆的摆幅、相位和实现初值自主确定并记录；实质范围、付费工具或不可获取参考等缺口才需澄清。

## 2. 分层、素材与静态还原

- 建立远景、中景、可玩/主体层、前景的空间关系，另记录实际绘制深度。水面、光束、雾等可独立存在于这些空间层内；不是强制只有四个节点。
- 不同形变、路径、视差或生命周期的元素独立交付。保留静态装饰，刚性洞壁/道路不跟动件整体扭曲。展示角色与实际控制角色分清所有权。
- 原件、可编辑母版、运行导出分开；统一画布、尺度、锚点、透明边缘、命名及运动余量。需要隐藏面时补齐，并记录为补绘而非原图恢复事实。
- **动件拥有唯一的可见来源。** 扫描背景、洞顶、ROOT、补底等实际像素，移除重复烘焙的鱼/细丝/气泡/角色/光斑；同时保留骨枝、墙体等静态结构。先检查素材再判类别。
- 固定镜头先在引擎重构静态画面，对照轮廓、道路高度、比例、光向、冷暖和遮挡；主要差异修正后再批量动态化。MP4可作参考对照，不能作为“分件场景重建”。

## 3. 先单件样板，再实例化

1. 先读配方库中适用分支，优先复用已验证素材和方法。用户认可的单件只证明该版本/尺度的表现，迁移对象仍需样板。
2. 把复杂运动分成局部动作、全局路径、材质变化、相机变化和生命周期。分别制作与测试，最后组合。例如鱼先完成身体/尾鳍动作，再做队形；垂须先固定根部、设计末端相位，再做材质细化。
3. 选择确定性制作、绘画帧/骨骼或网格烘焙、局部Shader、位图实例池/粒子、模型参考视频等合适方法。模型和外部工具是可选工具，不预设每件都要生成视频。实际工具权限和费用规则继续生效。
4. 对单件输出透明素材、可编辑动作母版、帧率/周期/锚点/参数及独立预览。只有移动贴图不能代替需要轮廓变化的摆尾动作；路径型气泡无需伪造逐帧形变。
5. 独立样板通过后按实例规则接入。差异体现在尺度、位置、相位、速度和深度；同步运动只在有明确原因时采用。不要靠全局随机抖动代替设计。

详细制作、验收与接续见[执行与证据合同](references/production-contract.md)。用[元素与经验模板](assets/scene-motion.template.json)建本项目记录，可裁剪不适用字段，不把模板当成已完成结果。

## 4. 接入与验收

- 统一可暂停时钟；子件自播与场景外部时钟二选一。暂停保持当前姿态，零速不回首帧；恢复、重载、回收、换场景分别检查。
- 在目标运行尺度检查附着、材质、遮挡、边缘和运动幅度；镜头变化仅按任务需要实现，并补足其合法范围内的余量。
- 先单件隔离检查，再整体播放。检查循环位置与速度、帧序、透明边缘、瞬移、实例数量/上限与重复来源。独立周期不同，不要求整场景短周期同步归零。
- 实际启动当前主场景，而非只运行历史预览。涉及构建则先在临时构建验证，再替换既有包；不自动发布公网或改玩家真实存档。
- 技术检测、实机静帧、连续播放观察和用户审美确认分别记录。没观察就写未验证，不用文件数/零报错/历史报告代替验收。性能单独不录制采样。

## 5. 主动提炼成功方法

每批结束都执行一次经验回写，不等用户提醒：

1. 从实际结果中提炼“对象为什么成功”，记录固定约束、运动分解、工具职责、可编辑输入、验收证据和适用边界。
2. 在本项目记录中保留细参数与失败返修；通用库只增加已验证且能改变制作决策的配方。推测性的迁移写candidate，成功实例写validated，用户认可单独记录。完整场景通过与单件获认可不能互相替代。
3. 鱼群/垂须/气泡等新实例先匹配已有配方，能归入同一机制就补充已有条目，不为每个名字新增流程。迁移时改附着方式、物理介质、尺度与节奏，而非照抄数值。
4. 用户当前任务允许修改此Skill时，更新[配方库与证据索引](references/motion-recipes.md)；全局安装只读或维护权限不足时，把待提升条目写项目进度并说明，不声称全局已学会。维护单一主源，安装映射指向同一套文件。
5. 将方法和对应母版/脚本/证据关联，记录版本。源素材、注册锚点或播放算法变化时撤销受影响检查的“当前通过”状态并复验；显示名变化无需重做素材。

这不是自动训练模型；经验体现在持续维护的Skill、配方和项目记录，供后续任务读取。

## 交付与接续

交付本次范围内的工程/独立场景、运行素材、可编辑母版、元素覆盖与方法选择表、实机证据、操作说明和限制。保存每个元素的状态、上次证据、输入摘要、外部任务ID及下一具体动作；中断后复用已有任务和成功阶段，不从头重新生成。

仅创建/调整Skill时，验证触发描述、引用、模板和选型案例即可；不因此运行模型、收费服务或修改游戏。项目示例可参考已有工程，但本Skill的执行不依赖特定项目磁盘路径。
