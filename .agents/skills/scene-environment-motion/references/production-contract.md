# 执行、证据与接续合同

## 记录与阶段

模板在`assets/scene-motion.template.json`，复制到当前项目的制作记录目录后填真实输入。示例是字段合同，不是验收结果。对小修可用等价表格，不要求为每个微调建立大项目结构。

| 阶段 | 最小产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| scan | 参考图实际查看、视频时间戳、逐区元素、静动判断与理由 | 指定范围已扫描，未知项列出，方法有依据 |
| layers | 原件、干净底图、分件素材、蒙版/隐藏面、所有权映射 | 分件有锚点与余量，重复来源已清理 |
| static | 目标引擎固定镜头实际截图 | 主要构图/轮廓/光向/比例正确，差异已定向返修 |
| pilot | 一个代表元素的母版、运行资源与独立预览 | 动作/路径/生命周期适用检查通过，工具实际可调用 |
| integrate | 实际场景节点、参数、实例数量或生成规则 | 全部预期实例接入，统一时间/遮挡，未污染其它场景 |
| validate | 实际运行、循环与状态证据、相机和性能检查 | 必需检查通过；未观察维度不能写passed |
| learn | 版本、结论、成功配方与失败修复 | 更新项目记录及适用经验库，保存下一动作 |

每步先保存具体指令：输入路径/摘要→目标元素→工具与参数→预期文件→验收动作→失败后只改哪里。然后实际调用工具。成功后继续就绪项，失败保留日志和原始输出。最多三次同类局部返修作为默认上限；更高成本/外部服务遵守其授权与重试规则，不能无限换模型重试。

## 静动判断与选型记录

每件元素必须有判断，不要求每件都动。例：一块洞壁保持static；珊瑚如果参考没有运动且尺度很小可static；柔性长藻为motion candidate；不清楚是帘还是柱子为inspect，先查看资源/时间样本再决定。推断可使用保守设计值，但不能把未确定项默认为通过。

动态结构分别填写：

- 固定端/附着面、自由端、运动包络；可运动的关节/膜与不可形变的硬结构。
- 单体轮廓动作、路径/队形、材质/光度、相机响应、生命周期分别属于谁。
- 循环或单次；周期/FPS/速度关系、相位及错开策略；隐藏/离屏/遮挡后的行为。
- 首选与备选、选型原因、工具实际能力与成本；保真度、编辑性和运行成本如何取舍。
- 预期资产、实例数量或生成规则、目标节点、碰撞/交互/声音是否适用及理由。

## 素材及循环

保留原件、生成原始结果、编辑母版与运行导出；图集是派生文件。记录透明区域、画布、固定锚点和边缘余量，禁止每帧各自紧裁缩放。浅底/深底分别看细丝、半透明膜和光效；alpha零下的RGB不构成可见背景残留证据。

轮廓型动画检查身份/长度、根部、局部摆幅、下游延迟和形变折叠；分层位图不能把固定建筑带着动。复制循环首帧到末帧不保证速度连续；输出通常不包含重复闭合帧，接缝与普通帧间变化比较。

FPS、时长、分辨率按用户和项目读取，不将案例12FPS设为所有项目的要求。如果当前项目采用“整秒向上取整”规则，才用 `ceil(实际解码帧数/源FPS)*目标FPS`；例如73/24秒在12FPS约定下为48帧。记录截取、放慢、补间或后期拟合，不能暗称原速直接抽帧。GIF时间精度与正式序列帧/引擎时间轴分开说明。

模型辅助制作先做小样。保留提交任务ID，再查询同任务；超时不新建重复任务。生成镜头漂移、轮廓融合与颜色闪烁需拒绝或修正；保留受控轮廓的后期应注明，不冒充模型原始结果。工具不可用时在已授权能力内采用适合的替代，不虚构调用。

## 运行与验收

1. **覆盖**：元素ID、静态簇、实例生成规则和实际资源引用对应。数资产、场景根节点、子实例分开。
2. **单件**：时间零、极值、转向、循环接缝、明暗底、固定根点；只推进本动件确认刚性邻区不变。
3. **整体**：至少观察数轮关键循环及持续系统的稳定段，按实际周期和风险选择时长。多组独立周期无需短周期整场同步闭合。抽样/加速模拟不能写成全程逐帧人审。
4. **状态**：暂停/恢复、动画开关、零速、确定性重载、离屏回收/换场景；不双重累计时钟，不恢复时突发补发。
5. **镜头/交互**：适用镜头边界与缩放，前后遮挡，已有主控移动时显示；纯环境不增加玩法碰撞。检查所有受同一素材影响的场景。
6. **性能/独立运行**：分开测录制吞吐和不录制帧时间，记录分辨率、设备、渲染器、内存、实例上限。约定构建需独立启动验证；未要求构建不强制重导整包。

每项保存status（not_run/pass/fail/not_applicable）、证据、执行人/方式、时间、输入版本。not_applicable需理由。脚本成功不代表审美通过；当前源码与历史报告分开。用户单件认可可以记为该件视觉认可，但不能免去场景接入检查。

失败按所有权定位：显示棱角先查光效有无背景几何；重复细丝先查ROOT和底图；前景直切先查遮罩/补底与相机；尾摆僵硬先查固定点、幅度传播和相位；气泡突发先查预热/回收/时钟。不要用增加粒子或全局模糊遮盖结构错误。

## 接续与方法提升

记录完成/失败/未测、上次输入摘要、生成任务ID、受影响依赖、下一条具体动作。先复验过期结果，再继续未完成项。恢复已有有效任务，保留人工编辑；重建脚本会覆盖母版时先保存副本并注明。

方法提升写入配方库前，检查：有实际资产和证据吗？成功在什么尺度/介质/引擎条件下？哪个步骤贡献最大？发生过什么失败？新对象为什么适用、哪里需要改变？新增条目应帮助选型或规避真实问题，不累积空泛口号。

纯Skill维护时检查结构、链接、模板及典型场景选型；不执行生产。文档检查不能登记成生产验收，案例推演不能登记成实际生成成功。
