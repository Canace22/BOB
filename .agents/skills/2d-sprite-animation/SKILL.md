# 2D 序列帧补动画

把已有角色补成可播放、可接入游戏的动作。保留角色身份与美术风格，交付真正变化的姿势、逐帧时间和稳定的坐标约定。不要把整图平移、旋转、缩放、透明度变化或状态图轮播叫作补齐动画。

## BOB 项目接入

本目录随仓库保存，动画任务优先使用此项目版本，无需依赖本机全局 Skill。同步自通用 `2d-sprite-animation`（2026-11-02）；后续同步时保留本节和项目相对路径。

制作前读[协作规则](../../../AGENTS.md)和[美术风格](../../../assets/art-style.md)。制作源与平台工程放 `assets/source/`，游戏导出放 `assets/runtime/`，按[美术资源接入](../bob-art-integration/SKILL.md)维护台账；接入正式 `game/` 时配合 [Godot 开发](../godot-game-dev/SKILL.md)，将实际验收记录到 `game/progress.md`。仅同步本 Skill 不代表已制作动画或完成游戏接入。

## 默认使用 Framecraft 工作台

优先用 [Framecraft / sprite-workbench](https://github.com/Canace22/sprite-workbench) 整理素材和制作预览，操作前读 [平台工作流](references/framecraft-workflow.md)。复用已安装的平台和已有工程，不默认另写一套处理台或预览页；用户指定其他工具时沿用用户选择。平台不可用时先处理具体启动问题，仍无法运行则说明缺口，使用最小替代流程继续。

- **只有静态角色、缺少动作**：先按下文制作连续姿势，再导入平台。平台本身不生成动作，也不提供动作补间；Real-ESRGAN 平滑只增强画面细节。
- **已有连续帧或角色动作视频**：直接在平台导入、按需抽帧/抠图、检查顺序与节奏、预览并导出。不需要的处理跳过；本来透明的帧不默认再次抠图。
- **需要游戏接入**：保留平台工程及原始导出，另外核对游戏使用的时长、循环和公共锚点。平台预览不能代替实际游戏状态切换验收。

## 先确定一个动作

读项目相关约束、原图、素材登记和当前加载位置；先看图，再选材。区分静态图、不同状态、连续动作帧；确认当前运行实际引用的是哪一份。原图不覆盖，试验帧与正式资源分开。

用一段简短说明固定：

- 动作、方向、固定视角、原地或带位移、循环或单次、进入与退出状态。
- 角色主参考、肢体身份、装备持握手和挂点；主参考缺失时先找项目中已认可的图。
- 相位顺序、总时长或每帧时长、目标游戏尺寸、移动速度。
- 等尺寸画布、共享缩放、根部锚点、地面基线、完整动作所需留白。

初次试验优先一个短动作。**关键事件数不等于最终播放帧数**：先验证接触、承重、转折、恢复等相位，再按运动变化补过渡。绘制多少姿势、各姿势停留多久，取决于动作时长、游戏风格与目标节奏；不预设固定八帧，也不对所有动作一律加帧。快速变化处可增加采样，停顿与恢复可延长持帧，各帧不必等时长。循环中不要重复放入第一帧作为末帧；落地和攻击通常播放一次，再回到待机。

已有连续帧时先检查并修复时序或对齐问题；需要从动画、视频取得动作依据时，读 [动作参考](references/reference-motion.md)。只拆出参考帧，并没有获得适合目标角色的新动画。

## 制作连续姿势

短序列可一次绘制为等格图集，提供同一角色主图、固定视角和明确相位表。动作参考约束姿势和节奏，角色主图约束造型、服装、材质与配色；两者不要混为同一来源。

走路需要看到双腿交替接触、承重、经过、抬起；落地需要接触、缓冲、最低点、回弹和恢复。检查实际输出的相位与顺序，不能只相信生成提示。发现同姿势重复、手脚数量变化、道具换手或相位缺失，先修这一处；错误相位不能靠插值或追加帧修好。相位成立后，再通过播放决定哪里补过渡、哪里调整持帧。

保持镜头、像素尺度、骨段长度、躯干体积与光照连续。生成前选定主参考姿势及稳定部位的尺度，后续关键帧沿用；先检查关键帧尺度，再制作过渡，避免把大小漂移扩散到整段。配件可随运动摆动，但连接关系不变。角色有非对称装备时，不靠镜像生成另一半步态或另一方向；镜像会把持握手和挂点一起交换。

项目已有专门风格规范时沿用。需要参考实际成败判断时，读 [BOB 试验记录](references/bob-trial.md)；案例中的角色挂点、素材尺寸和采样数量不作为其他项目的默认值。

## 整理帧与播放数据

按平台工作流导入已校准的帧。保留来源时间线；导入格式只有统一 FPS 时，将持帧按时间线展开，或使用经验证支持逐帧时长的调参工具，不能把不等时长姿势直接等速播放。重复持帧只表达停留时间，不计作新增姿势。

保存原始图集、裁切顺序和原始透明通道。先检查实际布局：请求等格并不保证生成结果等格。布局不规则时，为每帧记录显式 `rect` 和独立的注册 `offset`，分别定义从哪里裁切、怎样放入共同画布；不要直接按图宽平均切格。整段保持同一像素尺度、输出画布和公共 pivot。**不要逐帧把可见 bbox 缩放到相同大小**，也不要按每帧最低像素重新贴地：斗篷、武器和抬起的脚都可能改变 bbox。

以根部轴线和接触阶段的脚校准位置，保留动作本身的上下承重变化。根部对齐后仍要单独比较双脚间距、支撑脚接触点和局部轮廓：注册位移不能修复双脚相对滑动、头部体积变化或披风形变，这些需回到绘制阶段修正。检查最大姿势是否越格、裁肢或含相邻帧残片。游戏已有动态阴影时，不把固定地面阴影烘进角色。

### 必做：角色尺度一致性检查

**画布等大、PNG 无损或锚点对齐，都不能证明角色大小稳定。** 对已有素材也执行此检查，不能因未重新生成就跳过。

发现漂移时读 [尺度修正经验](references/scale-repair.md)，先区分显示缩放、整角色缩放和局部比例变形。优先保护原图细节；需要图像编辑时，以认可的姿势为统一参照，先修问题帧再检查整段，避免多轮整张图集重绘累积损失。

- 选一张认可的主参考，在固定显示倍率、公共根部和同一画布下，对照每个不同姿势及相邻帧；用叠图或并排检查躯干、头部及主要肢体的相对比例。循环还要检查末帧接回首帧。预览关闭逐帧自动适配缩放，排除显示方式造成的假漂移。
- 选择至少两个在当前视角可比较的稳定部位或标记距离，按角色结构选取，例如头身比例、躯干宽度、可比较的肢段长度或固定结构标记间距；记录可疑帧和相对参考的变化。遮挡、转身或透视缩短时不强行套用同一二维宽度，结合相近姿态判断。抬臂、展翼、伸展造成的整体外接框变化不作为缩放依据。
- 确认为整角色同比例漂移时，按稳定部位估计统一比例，以公共根部为中心校正该帧，并记录缩放与偏移；禁止按每帧 bbox 归一化。若仅某个身体部位或固定配件的比例变化，整体缩放不能修好，应局部修绘或重生成问题姿势，再检查前后过渡。
- 修正后重新播放整段，并核对平台处理前后及最终导出，确认没有引入根部跳动、脚滑或裁切。明显且无法由动作/透视解释的大小漂移未解决时，只能交付标明问题帧的候选，不能宣称动画可用或美术验收通过。用户指出漂移即作为待修缺陷记录，不能用技术检查通过抵消。

修正交付应提供原版／修正版同倍率、同时间轴的同步对比，支持正常速度、慢放与逐帧。分别报告尺度改善、纹理/姿势变化和真实生成分辨率；用户认可某项改善，不自动等于整段动画或游戏接入通过。

播放数据至少记录：帧顺序、每帧时长、循环与否、画布、公共 pivot、地面线、方向和预期显示尺寸。位移由游戏控制的步态应按实际移动距离或明确步幅推进；受阻停止时不能继续原地走。实际脚滑仍需观察，公式正确不等于自然。

## 播放验收与交付

优先用平台的动画预览与同步压缩对比检查，同时查看放大细节与实际游戏尺寸。只有平台无法覆盖所需的位移、状态切换等验收时，才补充最小游戏预览。循环至少观察数轮，单次动作观察进入与恢复。预览中停在末帧不等于已经验证“动作结束→原有待机”的衔接；需要接入游戏时再验证实际状态切换、碰撞与控制恢复。仅做样例不修改正式角色加载逻辑或发布项目。

用真实图集和播放数据验证非等时长边界、末帧持帧后停止、重播、倍速、暂停及逐帧。自动播放和手动推进共用一个时钟；确定性录制接管时，应停止实时推进，避免动作被走两遍。逻辑时间检查与画面观察分别记录。

检查并记录这些情况：

1. 帧数、顺序、时长正确；循环末尾接回开头无明显跳变，单次动作不误循环。
2. 角色轮廓、肢体数量、装备和握点连续；根部无意外横跳，身体无无故变大变小。
3. 接地脚稳定；在目标速度下无明显滑步；落地脚碰地后有缓冲而非穿地。
4. 开始、停止、转向、受阻和暂停恢复符合状态；未制作的方向不冒充已支持。
5. 代表性背景、实际尺寸和最大姿势下，透明边缘、辨识度与裁切正常。

分别报告计算检查、实际播放观察和未测项目。静态拼图、帧索引测试或构建通过，不能证明动作流畅；代理检查也不等于用户美术认可。相同问题连续三次仍未修好时保留最佳候选，说明缺陷与下一种可行修法，不继续盲目追加帧。

交付原图集、顺序帧或可用图集、播放数据、来源和许可记录、预览与已知限制。使用平台时同时交付 `.framecraft` 工程；保存后重开，确认帧序、节奏及处理结果恢复。读取实际导出文件验证，不把界面设置当作导出元数据已正确的证据。按项目格式接入，不强制绑定某个引擎。未经验证的输出标为候选。

## 选用边界检查

- “用这张 PNG 补一段走路，看看脚滑不滑。”：适用，先验证双腿相位，再决定过渡帧和节奏并播放检查。
- “拿一段获准使用的视频参考，给现有角色补落地。”：适用，先提炼相位，再重绘目标角色；不能把视频截图直接交差。
- “把已有动画帧放进工作台，压缩并导出游戏图集”：直接使用平台流程，不重新生成动作。
- “给 3D 人物重定向 FBX”：不适用，不为其扩写骨骼处理流程。
