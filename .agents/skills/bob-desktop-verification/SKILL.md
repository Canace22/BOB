# BOB 桌面回归验收

从本轮 diff 和[协作规则](../../../AGENTS.md)确定受影响版本，再读取对应 README 与测试脚本。通用浏览器操作和开发循环复用 `develop-web-game`；本文件提供当前项目的命令与限制。

## 启动和测试入口

需要 Node.js / npm；新版需先安装 Three.js，浏览器测试另需可导入的 Playwright 和 Chromium。启动命令在各版本目录运行，保持服务终端开启，再用另一个终端执行测试。

| 版本 | 启动 | 语法检查 | 浏览器回归（在该版目录运行） |
| --- | --- | --- | --- |
| 初版 `mvp/` | `npm start`，默认 4173 | `npm run check` | `node tests/playthrough.mjs`、`node tests/recovery.mjs` |
| 新版 `mvp-nightmare/` | 首次 `npm install`，再 `npm start`，默认 4174 | `npm run check` | `npm test` |

- 新版测试支持 `BASE_URL`、`TEST_OUTPUT`、`HEADED`，例如 `BASE_URL=http://127.0.0.1:4175/ npm test`。依赖安装见[新版说明](../../../mvp-nightmare/README.md#检查与验收)；也可通过 `PLAYWRIGHT_MODULE` 指向已有可导入入口。
- 初版两个测试目前硬编码 4173 和作者机器的 Playwright 绝对路径，不支持上述环境变量。运行前检查依赖是否存在；换环境时按本次需要做最小的路径适配并记录，不能宣称设置 `PLAYWRIGHT_MODULE` 即可运行旧脚本。
- 初版检查脚本的覆盖缺口见协作规则。修改未覆盖的 JS / MJS 时补跑 `node --check`；语法通过不代表关卡数据或玩法正确。
- 输出位于对应版本的 `output/playthrough/`、初版另有 `output/recovery/`。新版支持改输出目录，初版有相对工作目录的截图路径，应在 `mvp/` 内运行。重跑会覆盖同名证据，有保留需要时先归档。

## 项目中的关键约束

- 两版都暴露 `render_game_to_text()` 和 `advanceTime(ms)`。前者读取状态，后者会进入手动推进时间模式；测试开始使用后继续显式推进，不能只等待真实时间。通关证据使用真实按键或按钮，不用改写状态或传送替代路线验证。
- 初版存档键是 `whalefall-mvp-v1`，新版为 `bob-nightmare-25d-v1`。新版脚本已有旧存档哨兵检查；两版是否互不覆盖应在同源下检查，默认不同端口天然隔离，不能用不同端口证明键隔离。使用隔离浏览器上下文，避免清理用户真实存储。
- 初版主要验证共鸣、平台与三阀，另有恢复脚本；新版验证搬箱、纵深交互、潜行、顺序解谜与追逐。专项通过仅证明脚本实际覆盖的行为，不能推广为全部功能通过。
- 新版脚本当前以 `--enable-unsafe-swiftshader` 启动 Chromium。启动失败或超时先记录环境与错误；变更渲染后端时记录差异，不把灰溪镇的 Metal 参数直接当作 BOB 已验证方案。

## 五组验收与交付

按影响选 3–5 条，区分执行结果和待执行项：

1. **加载与入口**：进入游戏、开始/继续按钮、资源请求和控制台；新版检查 WebGL，初版检查原画是否真正加载，避免被程序背景回退掩盖。
2. **真实输入与路线**：移动、跳跃、碰撞、机关和出口；新版另看纵深、搬箱、蹲下、潜行与追逐，初版看共鸣距离与重复触发。
3. **状态与恢复**：死亡、重试、暂停/继续、刷新、重新开始、相关存档兼容与两版键隔离。坏档、失败重试等不在现有脚本覆盖内的行为，按需求另测。
4. **画面与声音**：实际打开截图检查遮挡、界面溢出和交互提示，窗口至少覆盖本次目标尺寸。音频采样只能证明输出和电平，听感需实际试听；截图和历史记录不代表用户已认可。
5. **发布路径**：涉及发布链路或资源时，在 `mvp/` 执行 `npm run build:pages`，检查 `.pages-dist/` 的根入口跳转、`nightmare/`、`mvp/`、Three.js vendor 及原画。使用支持静态路径的服务，带项目目录前缀打开验证；开发服务器通过不能替代项目站点路径检查。

发布构建会重建 `.pages-dist/`，保留所需旧产物后再执行；构建不推送。仅在用户要求发布时执行 `npm run deploy`。

脚本失败先保留证据，修复对应问题再复跑受影响检查。结论写入对应版本 `progress.md`，注明命令、环境、覆盖范围和证据位置；静态检查、浏览器运行、视觉检查及用户反馈分别报告。
